## 1. 基本操作

### 1-1. 画面構成

| 位置 | 内容 |
|---|---|
| 左サイドバー | メニュー（ロールにより表示が変わる）。左上の ⊏ で折りたたみ |
| 上部中央 | **検索バー**（顧客・案件・リードを横断検索） |
| 上部右 | プレゼンモード / **＋追加** / 通知 / アカウント |

### 1-2. 覚えておくと速い操作

| 操作 | 方法 |
|---|---|
| 検索にフォーカス | **`/` キー** |
| 何かを新規作成 | 右上の **＋追加** |
| 一覧の続きを読む | 下へスクロール（自動で追加読込） |
| その場で編集 | 一覧のヨミ・金額・次アクションは**クリックして直接編集**できる |
| 詳細を開く | 行をクリック → **サイドパネル**が開く（一覧の状態は保持される） |
| サイドパネルを閉じる | **Esc** または ✕ |

### 1-3. 金額の入力

金額欄は入力中に **自動で3桁カンマ**が入ります（例：`1500000` → `1,500,000`）。
桁の確認がしやすくなっています。**税抜**で統一してください。

## 3. ホーム

### 3-1. ダッシュボード

**今月の着地と打ち手を一目で確認する起点画面。**

| 見るもの | 意味 |
|---|---|
| 目標 / Commit / Best Case / Weighted / Gap | 今月の着地見込みと目標との差 |
| 危険案件 | 放置（7日以上動きなし）・次アクション未設定・提案後フォロー漏れ |

**使い方**：朝一番に開き、Gapがマイナスなら「どの案件を上げるか」を決めます。
危険案件は**その日のうちに手を打つ**か、ヨミを実態に合わせて落とします。

### 3-2. 今日のアポ・AC

**その日の商談予定と、やるべき次アクション（AC）の一覧。**

**操作手順（商談後の記録）**：
1. 該当の商談行を開く
2. 活動内容を記録（誰と・何を話したか）
3. **次アクションの日付と内容を入力**
4. ヨミが変わったなら更新して保存

> 💡 **商談終了後5分以内**の記録を推奨。この画面だけで完結します。

### 3-3. AI確認キュー

**夜間バッチが作成したAI要約の下書きを確認する画面。**

**操作手順**：
1. 確認待ち件数を確認する
2. 各項目の要約内容と元の商談記録を照合する
3. 誤りがあれば商談側で修正する
4. 問題なければ **「確認済み」** にする

> ⚠️ AI要約は**下書き**です。未確認のまま放置せず、事実確認をしてから確定してください。

### 3-4. タスク

**担当・期日でタスクを管理。リスト / ボード / カレンダーで切替できます。**

- チェックで完了
- 上位の器として **プロジェクト**・**ポートフォリオ**・**ゴール** があります
- 商談後の作業漏れは **タスク → 商談フォロー** で確認できます

### 3-5. 活動履歴

案件・顧客に紐づく活動（商談・電話・メール・DM・提案・見積・フォロー等）の記録一覧です。
**活動を登録**からいつでも追加できます。

### 3-6. マインドマップ（代表・管理者）

**予定と段取りを1枚に整理する画面です。** カレンダー・案件・ヨミを取り込み、抜けている準備を洗い出します。

- 「週次予定を自動生成」から、その週の予定をもとにマップを作成できます
- 作成したマップは全画面のプレゼン表示に切り替えられます

## 4. 案件

### 4-1. アポ・商談登録

**アポが取れたときの入口。案件と初回商談を同時に作成します。**

3つの起点から登録できます：

| 起点 | 使う場面 | 挙動 |
|---|---|---|
| **リードから** | 展示会・セミナーで獲得した相手 | 詳細情報が案件に自動コピー。リードは「アポ決着」に更新 |
| **既存顧客から** | 取引実績のある会社 | 顧客情報を引き継ぐ |
| **新規** | どちらにも無い場合 | 顧客を新規作成 |

> 💡 **必ずリード/既存顧客を先に検索**してください。新規で作ると重複の原因になります。

### 4-2. 案件（表・ボード）

**案件の一覧・編集を行うメイン画面。** `顧客 › 案件 › 商談` の階層で管理します。

**表示モード**：
- **案件一覧** — 表形式。**ヨミ・金額・次アクションはその場で編集可能**
- **商談一覧** — 商談単位の表示
- **ボード** — ヨミ別のカンバン表示
- **カレンダー** — 日程での表示
- **提案** — 提案状況の表示

**絞り込み**：担当・商材・流入経路・展示会施策・「次アクション未設定」「放置案件」

**便利機能**：
- 条件を **保存ビュー** として登録できます（`＋現在の条件を保存`）
- **CSV出力**（絞込済み全件）
- 右上 **商談チェック** で型の必須項目の入力漏れを一括確認

### 4-3. 営業ビュー

営業担当ごとの担当顧客・案件・見込み・次月目標の一覧。
名前をクリックすると**個人ダッシュボード**（担当顧客・商談予定・KPI・案件ファネル）が開きます。

### 4-4. 売上予測

**年度（7月〜翌6月）の目標と着地見込み。**

- `Weighted = 金額 × 確度` で加重集計
- 今月 / 来月 / 四半期 / 12ヶ月ローリングで確認できます
- **受注見込み（来期計画）** では、案件ごとに期間・売上・確度を入力すると
  月次の受注見込みが算出され、年度の着地計画になります

### 4-5. 目標入力

売上・成約・アポ・リードの**月別目標**を年度単位で設定します（**決算6月＝7月始まり**）。
営業マン別の月別売上目標もここで設定します。

### 4-6. 稼働報告

**デリバリー担当者が、担当案件の稼働実績を日次で記入する画面。**

**操作手順**：
1. 日付ごとに稼働時間を入力する
2. 行ごとの **「案件」** で原価の紐づけ先を選ぶ
3. 週の入力が終わったら **提出** する

**ステータスの流れ**：

```
下書き(draft) → 提出(submitted) → 承認(approved)
                              └→ 差戻し(returned) → 修正して再提出
```

> 承認された実績が **原価管理の実績原価** と **月次請求** の根拠になります。
> 案件に紐づかない稼働は「全般稼働」として承認のみされ、原価には反映されません。

## 5. 顧客

### 5-1. 顧客

会社の一覧。**累積売上の高い順**で追客優先度が分かるようになっています。
エリア・業種・担当営業で絞り込みできます。

一覧ヘッダーから **Sランク顧客攻略**（大手・中堅大手を部署別・キーマン別に横展開）と
**既存顧客深耕**（受注後のフォロー→追加課題→アップセル）へ移動できます。

### 5-2. 担当者

顧客企業のキーパーソンを管理します。決裁role・部署・役職・メールを登録します。

### 5-3. 名刺情報

メンバーが名刺交換したデータを組織で共有します。

**取込手順**：
1. Eightの「名刺データダウンロード」でCSVを出力
2. **取込**からアップロード（Shift_JIS / UTF-8 は自動判定）
3. 名刺交換者を選択（既定は取込者）
4. 会社名・氏名・メールでCRM顧客と自動マッチング

### 5-4. リード／リード取込

展示会・セミナーのリストを**優先度付け**し、架電 → アポ獲得まで管理します。

**取込手順**：
1. **リード取込**でTSV/CSVをアップロード
2. 列を対応づける（形式が変わっても対応可能）
3. 一括投入

アポが取れたら **アポ・商談登録** から案件化します（リードは自動で「アポ決着」に）。

### 5-5. メール

| 画面 | 用途 |
|---|---|
| **メール定型文** | お礼・資料送付・日程調整などのテンプレート。`{contact}` `{company}` が自動差込 |
| **メールを作成** | 定型文を選んで送信。「Gmailで開く」または「記録する」 |
| **メールシーケンス** | 「Day0お礼 → Day3資料 → Day7再打診」の多段フォローを自動送信 |
| **メール送信アカウント** | 自分のメール（Google Workspace / Zoho）をSMTP接続 |
| **メール成果** | 開封（近似値）・クリック・返信の実績 |

> シーケンスは**受注/失注/アポ化で自動停止**します。

### 5-6. ノウハウ・事例

商談で得たノウハウ・成約/失注理由・刺さる事例を蓄積し、必要なときに検索します。
関連画面として **カトルセの型**（業種×規模×役職別の勝ち筋）があります。

### 5-7. AIヘルプ

**システムの使い方や自社の型について、AIに質問できる画面です。**

- 「質問する」に自然文で入力すると回答が返ります
- 「このAIが見ている資料」で、回答の根拠にしている資料を確認できます

## 6. 分析

### 6-1. 営業レントゲン

**売上を因数分解して、悪化している箇所を診断する画面。**

```
売上 = リード数 × アポ獲得率 × 商談実施率 × 受注率 × 平均単価
```

どの因数が悪化しているかを診断し、**改善インパクトの大きい順に処方箋**を出します。
毎月1日に前月分が自動保存され、**分析履歴**で推移を比較できます。

### 6-2. 分析ハブ

各種分析の入口です。主なものは以下の通りです。

| 分析 | 分かること |
|---|---|
| 失注/成約 分析 | なぜ勝った/負けたか（理由・競合・カテゴリ・月別） |
| 営業マン別分析 | 担当者別の行動量・受注率・単価・放置案件 |
| 商品別 / プロダクト収益 | 商材別の成約率・単価・粗利・LTV・MRR |
| 流入元 / 施策ROI | 流入元・施策別のコスト/獲得/受注/ROI |
| 展示会分析 / 展示会選定 | 展示会別のCPL/CPA/CPO/ROI、出展候補のスコアリング |
| セミナー分析 / 攻略リスト | 満足度・課題からホットな見込みを抽出 |
| ステージ滞留分析 | ボトルネックと放置案件 |
| 期間比較レポート | 前月比／前年同月比 |
| トレンド分析 | エリア・業種・規模・コホート別の顧客分布 |

### 6-3. AI-PMO

鳥の目（俯瞰）・虫の目（詳細）・魚の目（流れ）・コウモリの目（ヌケモレ点検）で
振り返りと段取りを支援するアドバイザー機能です。

### 6-4. 経営レビュー（週次サマリー）

幹部MTG用。**週次サマリー**を起点に、部門横断でGood/Watch/Badを把握します。

| 画面 | 用途 |
|---|---|
| 週次サマリー | 課題のある項目に議論を集中させる |
| 営業KPI振り返り | 目標と実績の予実差・判定・対策 |
| 商談・読み管理 | 当月成約見込み・停滞・次回AC未設定の抽出 |
| 売上逆算 | 目標売上から必要な受注数・アポ数を逆算 |
| マーケ施策管理 / デリバリー品質管理 / 開発・顧問案件管理 | 各領域の状況把握 |
| アクション管理 / 振り返り履歴 | 決めた対策の実行状況と蓄積 |

## 7. レビュー

### 7-1. 週次レビュー

**「確認」で終わらせず、今週の打ち手を決めるための会議画面。**

**進め方**：
1. 数字（目標・着地見込み・Gap）を確認する
2. 危険案件・停滞案件を洗い出す
3. **案件ごとに「誰が・いつまでに・何をするか」を決める**
4. 決めた対策はアクションとして登録し、翌週に確認する

関連画面：**ヨミ変更履歴**（受注・オチ・定期追いへの変更理由を記入）、
**週報スナップショット**（その瞬間の数字を保存して過去と比較）

### 7-2. 営業マン別週報

**担当ごとの目標・実績・見込み・案件を自動集計する画面。**

**表示内容**：
- 今月目標 / 実績（受注） / 月末見込み / 達成率
- 目標 vs 実績の推移（週別・月別）
- ヨミファネル（ヨミ別の件数・金額）
- パイプライン現況（進行中案件・Weighted・今月クローズ予定・停滞/危険）

**月別ヨミ（成約計画：今月〜2ヶ月先）**：
- 表示切替 **「一覧」/「月別ヨミ」** があります
- 月別ヨミではさらに **「進行中のみ」/「決着含む全件」** を切り替えできます
  - **進行中のみ**（既定）：まだ残っているActive案件だけ
  - **決着含む全件**：受注（緑バッジ）・オチ（赤バッジ・取り消し線）も表示。当月の決着を振り返る用
- 案件をクリックすると右のサイドパネルが開き、**ヨミ・成約予定(月)・金額をその場で編集**できます（保存で即反映）

**記入すること**：先週の差分、今週の予定、1ヶ月先の予定を型に沿って記入します。

## 8. 原価管理（管理職）

> 表示ロール：代表 / 管理者 / Sales Ops / 経理 / 講師・PM

**受注後のデリバリー原価・粗利を、計画から完了実績まで管理する機能です。**

### 8-1. 一覧

原価管理対象の案件を、重要度と進行中を上位にして表示します。

| 列 | 内容 |
|---|---|
| 顧客 / 案件 | クリックでサイドパネルが開く |
| 重要度 | 高・中・低 |
| **担当（責任者）** | アサインした外注/社員から**責任者を指名**（その場で選択・即保存） |
| 期間 | 計画期間と進行状況（進行中 / 予定 / 完了） |
| 販売・原価・粗利・粗利率 | 月別計画の合計 |
| 提案可否 | GO / 条件付き / 要協議 |
| 稼働実績（承認） | 承認済み稼働の原価換算 |
| 進捗 / 完了実績・予実差 | 終了時の着地と計画との差 |
| 営業担当 | 案件のオーナー |

### 8-2. カレンダー（契約＋見込み）

**契約中・終了・継続見込み・新規見込みを1つのタイムラインで俯瞰します。**

**バーの見方**：

| 表示 | 意味 |
|---|---|
| ティール実線 | 契約中 |
| 淡いティール | 開始前（確定） |
| グレー | 終了 |
| **破線バー（色＝確度）** | 見込み。緑≥70% / 黄40-69% / 赤<40%。要手配は赤リング |

**上部の指標**：
- 今後6ヶ月の受注見込み（確度加重）
- 今後3ヶ月で要手配の人員 → **0でなければ採用/契約を急ぐ判断材料**
- 要アクション（調整期限が近い見込み）

**表示範囲の切替**：前後6ヶ月（既定） / 年度 / 全期間

**下段サマリー**：確定売上 / 見込み（加重） / 合計 / 必要人員（うち要手配）を月別に表示。
月ヘッダー・案件情報・サマリーは固定され、スクロールしても見えます。

**フェーズ紐づけ（🔗アイコン）**：
連続する案件（例：検討企画フェーズ → 伴走支援フェーズ）を紐づけると、
**同じ行にまとめて表示**されます。「◯◯案件の続き」を選ぶだけです。

**見込みの登録**：
- **＋見込みを追加** で手動登録
- または **対象候補タブ → 商談中案件の「見込み管理」ボタン**（基礎情報を引き継ぎ）
- 見込みには 期間・金額（月額/総額）・確度・必要人数・**人員手配状況**・**契約/採用の調整期限** を登録します

### 8-3. 対象候補

**原価管理されていない案件のうち、管理すべきものを自動抽出します。**

| 区分 | 条件 |
|---|---|
| **受注済み** | 受注したのに原価管理していない（デリバリーが発生する＝要対応） |
| **大型商談** | 商談中で金額が大きい（先行して計画すべき） |

**操作**：
- **対象化** … 原価計画を作成して管理を開始（見込みがあれば期間を自動引き継ぎ）
- **見込み管理** … 未受注のまま見込みとしてカレンダーで管理

ヘッダーは固定され、各列でソートできます（既定は日程が直近順）。

### 8-4. 稼働承認

提出された週次の稼働実績を **承認 / 差戻し** します。
承認済み実績が原価管理の実績原価・月次請求の根拠になります。
案件に紐づけると原価管理のアサインが作成されます。

## 9. バックオフィス

> 表示ロール：事務 / 人事 / 管理者。**営業データは表示されません**（仕様）

### 9-1. BOダッシュボード

納期のある事務作業を横断で見張る場所。ここを毎日確認するのが基本動作です。

### 9-2. 助成金トラッカー

研修の助成金対応を期日で管理します。

| 対応 | 期日の目安 |
|---|---|
| 事前説明会 | 研修前 |
| **事前申請** | **研修の1ヶ月前** |
| **実績報告** | **研修後2ヶ月** |

### 9-3. 展示会準備WBS

展示会を **「確定」** にすると、**タスクプリセット**からWBSが会期基準の期日つきで
自動生成され、納期前にリマインドされます。プリセットは編集できます。

### 9-4. 研修後フォローアップ

受注した研修案件を母数に、**1・3・6ヶ月後**のフォローMtgの日程調整・実施と、
AI活用度の進化・業務課題・提案・アップセルを追跡します。
**受注が発生すると自動で追加**されます。

### 9-5. AI講師スケジュール

講師の日程調整URLを登録し、どの講師がいつ・どの企業で研修を実施するかを
カレンダーで俯瞰します。

### 9-6. 事例インタビュー管理

研修受講会社への事例化を **未打診 → 打診 → 承諾 → 取材 → 記事化 → 公開** で管理します。

### 9-7. 講師アンケート分析

研修後アンケートを取り込み、講師別・研修種類別・受講者層別に品質を可視化します。

## 11. 設定

### 11-1. 設定（マスタ管理）

メンバー・商材・流入経路・展示会/施策をマスタとして管理します。
**ステージ・ヨミはシステム定義**のため変更できません。

### 11-2. 重複の検出とマージ

| 対象 | 判定 |
|---|---|
| 顧客 | 会社名（正規化）の一致 |
| リード | メールアドレスの一致 |

マージすると**関連データは残す側へ付け替えられ**、重複側はゴミ箱（30日）へ移動します。

### 11-3. ゴミ箱

削除したリード・案件・顧客は **30日間保管**され、復元できます。
30日を過ぎると自動的に完全削除されます。

### 11-4. データ取込

Notion「商談ヨミ表」のCSVをアップロードし、顧客 → 案件 → 商談ログへ取り込みます
（全置換のため何度でも再同期できます）。

### 11-5. AIバッチ運用

ジョブごとのスタート/停止と、夜間バッチの実績を管理します。
**停止中のジョブは実行されません。**

主な自動処理：

| 処理 | 実行タイミング（JST） |
|---|---|
| 日次ダイジェスト | 毎朝 8:00 |
| ワークフロー自動化の評価 | 30分ごと |
| メール受信同期 | 30分ごと |
| メールシーケンス送信 | 毎日 9:00 |
| AI-PMO 夜間処理 | 毎日 1:00 |
| 営業レントゲンのスナップショット | 毎日 0:30（月初に前月分を保存） |

### 11-6. ワークフロー自動化

「ヨミC転落 → Slack通知」のような軽量ルールを定義します。
有効なルールを短間隔バッチが評価し、**Slack・アプリ内通知・タスク起票**を自動実行します。

### 11-7. 監査ログ

ログインと重い処理（取込・書き出し・名寄せ・マッチング）を記録します。**閲覧は管理者のみ**。

## 12. 用語集

| 用語 | 意味 |
|---|---|
| **ヨミ** | 案件の確からしさを示す全社共通の物差し（0.受注〜9.調整中）。変更するとステージ・確度・ステータスが自動連動 |
| **Weighted（加重見込み）** | `案件金額 × 確度`。売上予測の基準値 |
| **Commit / Best Case / Pipeline / Upside / 除外** | 予測区分。Commitは固い見込み |
| **AC（ネクストアクション）** | 次にやること。日付＋内容で必ず設定する |
| **放置案件** | 最終活動から7日以上動きがない案件 |
| **リード** | 展示会・セミナー等で獲得した見込み客。アポ獲得で案件に昇格 |
| **案件（Opportunity）** | 顧客との取引1件。売上予測の最小単位 |
| **原価管理対象** | デリバリー原価・粗利を管理する案件（フラグで指定） |
| **アサイン** | 案件に割り当てた外注/社員。単価×工数で原価を計算 |
| **責任者（担当）** | アサインの中から指名する対応チームのリーダー |
| **見込み（デリバリー見込み）** | 確定前の継続・新規案件。確度・必要人員・調整期限を持つ |
| **要手配** | 必要人員が確保できていない状態。採用/契約を急ぐシグナル |
| **フェーズ紐づけ** | 連続する案件（前フェーズ→次フェーズ）を1行にまとめる設定 |
| **年度（FY）** | 決算6月＝**7月始まり**。FY2026＝2026年7月〜2027年6月 |
| **Sランク顧客** | 年間1,000万円以上を目指す重点取引先 |
| **WBS** | 展示会準備などの作業分解。プリセットから自動生成される |
