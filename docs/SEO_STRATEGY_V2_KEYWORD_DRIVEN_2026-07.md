# SEO戦略 v2 — 仮説駆動へ の再構成（2026-07-30）

**きっかけ**: 実装した機能をユーザーが実際に使って出た指摘。
> 「狙ったキーワードがまずあって、それが何位を取れているか、そこから問合せが発生しているか、という流れにならないか。仮説がないまま対処療法的になっている気がする」

**結論: 指摘は正しい。** 現行実装には**構造的な欠落**があった。本書でコンセプトを再定義する。

---

## 1. 何が欠けていたか

### 1.1 実装したもの

Search Console に出てきた語（**発見された1,735語**）の中から機会を探し、CTR改善やリライトを提案する仕組み。

### 1.2 欠けていたもの

**「何を狙うか」を決める部分。** ターゲットKW台帳は**0件**のまま、機能していなかった。

| | あるべき状態 | 実装した状態 |
|---|---|---|
| 狙うKW | 仮説に基づいて**先に決める**（台帳） | **決めていない**（0件） |
| 評価軸 | 狙ったKWが**何位取れたか** | 出てきた語のCTRが低いかどうか |
| 施策の起点 | 狙ったが**取れていない**KW | 既に表示されている語 |
| 競合 | 上位を取っている競合の**良い所を参考にする** | 見ていない |

### 1.3 これが何を招いていたか

実データが端的に示していました。提案の上位は全て：

`gpt image 2` / `claude code` / `codex` / `image2` / `notebooklm 使い方`

**これらは1つも「狙って取った語」ではありません。** AIツールの使い方を調べる個人が偶然たどり着いた語です。ここを磨いても、**¥150万の研修を検討する法人は増えません。**

私は intent_mix という検出で「流入の85%が情報収集層」と警告を出しました。**警告は出したが、「では何を狙うのか」を決める機能を作っていなかった。** 診断だけして処方をしない状態でした。

これがまさにご指摘の「**対処療法**」です。

## 2. 再定義: SEOコンサルは2つのループで動く

```
┌─ 上位ループ（Plan / 仮説）── 月次・四半期 ─────────────────┐
│                                                              │
│  ① 仮説を立てる                                              │
│     「AI研修の発注を検討する人事は、こう検索するはずだ」        │
│           ↓                                                  │
│  ② 狙うKWを台帳に決める（クラスタ・意図層・対策ページ）         │
│           ↓                                                  │
│  ③ ギャップを見る                                            │
│     対策ページが無い → 作る                                   │
│     あるが圏外      → 作り直す                                │
│     11〜20位        → 押し上げる                              │
│     10位以内        → CTRを上げる                             │
│           ↓                                                  │
│  ④ 週次で順位を追う（KW順位表）                               │
│           ↓                                                  │
│  ⑤ 取れた / 取れないを評価 → 競合の上位ページを見て学ぶ         │
│           ↓                                                  │
│  ⑥ 仮説を更新する ────────────────────────┐                  │
└──────────────────────────────────────────┼──────────────────┘
                                            │
┌─ 下位ループ（Do / 改善）── 日次 ───────────┼──────────────────┐
│  既存資産の最適化                          │                  │
│  ・CTR損失の回収  ・11〜20位の押し上げ      │                  │
│  ・内部リンク    ・順位低下の即日検知       │                  │
│  ＋ 拾い物の発見: 狙っていなかったが取れている語 → ⑥の仮説の種  │
└──────────────────────────────────────────────────────────────┘
```

**現行実装は下位ループだけでした。** 上位ループが無いと「今あるものを磨く」しかできず、
カトルセの場合は**磨く対象が全部第3層なので、いくら磨いても問合せは増えません。**

### 2.1 両方が必要な理由

| ループ | 効果 | 単独だとどうなるか |
|---|---|---|
| 上位（仮説） | 正しい的を狙える | 施策が大きく重く、3ヶ月成果が見えず続かない |
| 下位（改善） | 3〜14日で成果が見える | **的が外れたまま磨き続ける（今の状態）** |

**順序は 上位 → 下位。** 的を決めてから磨く。

### 2.2 「拾い物」の正しい扱い

狙っていなかったのに取れている語（`gpt image 2` の4,103表示など）は、捨てるのではなく**仮説の種**として扱います。

- 「GPT image 2 の解説記事で月4,000表示ある」→ **AIツール解説で集客できる実力がある**という証拠
- ただし発注検討層ではない → **そこから発注検討層への内部リンク導線**を作る、が正しい打ち手
- これは「第3層で集めて第1層に送る」という戦略で、当初の戦略ドキュメント §3 と整合します

つまり `gpt image 2` のタイトル改善は**間違いではないが、優先度が高すぎた**。第1層のKWを取る施策の方が先です。

### 3.3 この台帳で何が分かるか

台帳と Search Console の実データを突合すると、**狙ったKWが4つの状態に分類**されます。

| 状態 | 意味 | 打つべき手 |
|---|---|---|
| **未対応** | 対策ページが存在しない | **新規記事を作る**（第1層なら最優先） |
| **圏外** | ページはあるが検索結果に出ていない | 作り直す（内容が的を外している） |
| **11〜20位** | あと一歩で1ページ目 | リライトで押し上げる |
| **10位以内** | 取れている | CTR改善で刈り取る／守る |

**現状の予測**: カトルセは第1層40語のほぼ全てが「**未対応**」または「**圏外**」のはずです。実データで確認します。

これが「対処療法」と「仮説駆動」の決定的な違いです。前者は既にあるものしか見えず、**後者は「無いこと」が見えます。**

### 3.4 対策ページと実表示ページのズレ

台帳には「このKWはこのページで取る」という**対策ページ**を書きます。実際にGSCで表示されているページと違っていたら、それ自体が重要な発見です。

| ズレの状態 | 意味 |
|---|---|
| 対策ページ ＝ 実表示ページ | 意図通り |
| 対策ページ ≠ 実表示ページ | **Googleが別のページを選んでいる**。カニバリか、対策ページが弱い |
| 実表示ページが無い | 圏外 |

### 3.5 競合の扱い

**狙ったKWで上位を取っている競合の良い所を参考にする** — これはご指摘の通り必要です。

ただし検索結果の自動取得は規約とコストの問題があるため、**KWごとに「上位3社のURLと構成の特徴」を記録する欄**を台帳に持たせ、人（またはAI）が調べて入れる運用にします。

記録する内容の型：
- 上位3社のURL
- 各社の見出し構成の要点（何を網羅しているか）
- 自社に無い要素（＝リライトで足すべきもの）
- 自社にしか無い要素（＝差別化として強調すべきもの）

## 4. 運用リズムの再定義

| 頻度 | やること | 見る画面 |
|---|---|---|
| **毎日15分** | 下位ループ。今日の要対応と提案の承認 | 集客サマリー / 改善提案 |
| **毎週30分** | **上位ループの計測**。狙ったKWの順位を前週比で確認。大きく動いた語の原因を見る | **KW順位表**（新規） |
| **毎月1時間** | ギャップの棚卸し。未対応・圏外のKWから次の記事を決める。競合の上位ページを調べる | **KWギャップ** / 戦略ボード |
| **四半期** | 仮説そのものの見直し。取れなかったKWを捨て、拾い物から新しい仮説を立てる | 戦略ボード |

## 5. 実装への反映（F-307 として追加）

| # | 機能 | 内容 |
|---|---|---|
| 1 | **ターゲットKW台帳** | 仮説KWの登録（クラスタ・意図層・対策ページ・想定検索数・目標順位・競合メモ）。上記40語を初期投入 |
| 2 | **KW順位表** | 狙ったKW × 週次順位 × 前週比 × 対策ページ vs 実表示ページ。添付いただいた表と同じ役割 |
| 3 | **ギャップ分析** | 未対応 / 圏外 / 11〜20位 / 10位以内 の4分類。各分類から打ち手が自動で決まる |
| 4 | **提案生成の優先順位変更** | **台帳ギャップ由来の提案を最上位**に。GSC発見型（現行）は「拾い物」として後ろに置く |
| 5 | 競合メモ | KWごとに上位3社と学ぶべき点を記録 |

**重要な設計変更**: 提案の並び順は「期待売上 × 戦略係数」でしたが、**台帳KW由来かどうか**を最上位の判断軸に加えます。狙った的を外したまま磨き続けるのを構造的に防ぐためです。

## 6. 私の設計判断の誤りとして記録

**なぜ欠落したか**: 計測基盤（WO-30）から始めたため、「取れているデータから何が言えるか」という**データ起点の思考**に寄りました。SEOコンサルの本質は**仮説起点**であり、順序が逆でした。

`seo_keywords` テーブル自体は WO-32 で作っていましたが、**中身を入れる導線と、それを主役にする画面を作らなかった**ため、機能として存在していませんでした。テーブルがあることと機能があることは別です。

**教訓**: 「計測 → 分析 → 提案」の順で作ると、計測できるものしか提案できなくなる。**先に「何を目指すか」を入れる器を主役として作る**べきでした。
