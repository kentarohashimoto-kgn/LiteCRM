## 1. 背景・目的

契約済み顧客向けの **AI研修** において、受講者が最新の生成AIツールを「自分の手で」体感できる環境を提供する。ChatGPT / Claude の法人契約を顧客側で締結する前段階でも、研修の場で安全に・すぐに・会社ごとに整備された状態で生成AIを触れることが狙い。

- 研修講師（当社）側が事前にシステムプロンプトや参照アセット（例: デザインガイド）を仕込んでおくことで、「トンマナの揃ったスライド骨子を連続生成する」といった **業務転用イメージの湧く体験** を提供する。
- CRM（CATORCE Sales OS）の管理基盤・AI連携基盤・デプロイ基盤を再利用しつつ、**画面・認証は CRM と完全分離** する。

## 2. スコープ

### 2.1 対象（v1）

| 区分 | 内容 |
|---|---|
| 顧客向け画面 | 会社別URL + Basic認証 + 個別ログイン → ChatGPT/Claude ライクなチャットUI（左ペイン: 会話履歴、メイン: 一問一答） |
| モデル切替 | Claude 4種（Fable / Opus / Sonnet / Haiku）+ OpenAI 最新チャットモデル + 画像生成モデル |
| プリセット | 管理者が事前定義するシステムプロンプト＋参照アセット（テキスト/ファイル） |
| 管理画面 | CRM 内（管理者ロール限定）で 会社・利用者・プリセット・アセット・利用量 を管理 |
| 動線 | (1) CRM のメニュー / 管理画面からジャンプ (2) 顧客は会社別の個別URL（Basic認証あり）から入る |

### 2.2 対象外（v1）

- 顧客側でのセルフサインアップ・パスワードリセットメール（v1 は管理者がアカウント発行・再発行）
- RAG（ベクトル検索）。プリセットのアセットは「テキストのプロンプト注入」まで（既存 `document_chunks` 基盤の転用は後続フェーズ）
- Excel/CSV を**入力**として添付し、コード実行で分析させる用途（Files API の container_upload 経由。後続フェーズ）
- 会話の共有リンク・エクスポート
- SSO（Google ログイン等）
- 多言語対応（日本語のみ）
- モバイル専用最適化（レスポンシブで閲覧可能なレベルは担保）

## 3. 利用者・ロール

| ロール | 説明 | ログイン方法 |
|---|---|---|
| **受講者（trainee）** | 顧客企業の研修参加者。チャット利用のみ | 会社別URL → Basic認証 → 個別ID/パスワード |
| **CRM管理者（admin/owner）** | 当社側。会社・利用者・プリセットの管理、利用量閲覧、プレビュー | 既存 CRM ログイン（Supabase Auth） |

- 受講者は CRM のユーザー（`memberships`）とは **完全に別系統** のアカウントとし、CRM 側データには一切アクセスできない。
- 顧客企業側の管理者ロールは v1 では設けない（設定変更はすべて当社管理者が行う）。

## 4. 主要ユースケース

- **UC-1 研修準備**: CRM管理者が会社を登録 → Basic認証情報とスラッグを決定 → 受講者アカウントを一括発行 → プリセット「スライド骨子作成（デザインガイド注入済み）」を登録 → 接続情報（URL / Basic認証 / 個別ID）を顧客へ共有。
- **UC-2 受講者の体験**: 受講者が会社別URLへアクセス → Basic認証 → 個別ログイン → モデル「Claude Sonnet」を選択して質問 → 回答をストリーミングで閲覧 → モデルを「画像生成」に切り替えてバナー画像を生成 → 履歴から前の会話に戻る。
- **UC-3 トンマナ統一体験**: 受講者がプリセット「スライド骨子作成」を選んで新規会話を開始 → 管理者が仕込んだデザインガイドに沿った骨子が連続生成される。
- **UC-4 研修モニタリング**: CRM管理者が会社別の利用量（トークン・リクエスト数・画像生成枚数）と会話一覧を確認し、研修の振り返りに使う。
- **UC-5 プレビュー**: CRM管理者が管理画面から「この会社の環境を開く」で受講者と同じ画面を確認する。

## 5. 機能要件

### 5.1 認証・入場（AL-1xx）

- **AL-101**: 顧客向け環境は `https://<APP_URL>/lab/{company_slug}` の **会社別個別URL** で提供する。スラッグは会社登録時に管理者が指定（英小文字・数字・ハイフン、全社ユニーク）。
- **AL-102**: `/lab/{slug}` 配下への全アクセスに **HTTP Basic認証** を要求する。ID/パスワードは会社ごとに管理者が設定。未認証・不一致は 401（`WWW-Authenticate: Basic`）。
- **AL-103**: Basic認証通過後、**個別ログイン画面** を表示する。ログインID（会社内ユニーク）＋パスワードで認証。
- **AL-104**: ログイン成功で署名付きセッションCookie（HttpOnly / Secure / SameSite=Lax、有効12時間）を発行。以後 `/lab/{slug}` 配下の画面・APIはセッション必須。
- **AL-105**: ログイン失敗が **連続5回** で当該アカウントを **15分ロック** する。ロック中はエラーメッセージで残り時間を案内しない（「ログインできません。時間をおいて再度お試しください」）。
- **AL-106**: ログアウト機能（セッションCookie破棄）を左ペイン下部に置く。
- **AL-107**: 無効化された会社（`is_active=false`）・利用者は、Basic認証/ログインを通しても入場不可（「この環境は現在利用できません」）。
- **AL-108**: 別会社のスラッグ配下では自社セッションは無効（セッションは会社IDに紐づく）。

### 5.2 チャット（AL-2xx）

- **AL-201**: メインペインで一問一答形式のチャットができる。送信は Enter（Shift+Enter で改行）またはボタン。
- **AL-202**: テキスト回答は **ストリーミング表示**（逐次描画）。生成中は停止ボタンを表示し、停止時点までの内容を保存する。
- **AL-203**: 回答は Markdown レンダリング（見出し・箇条書き・表・コードブロック＋コピー用ボタン）。
- **AL-204**: 会話はマルチターン。過去メッセージを文脈としてモデルに渡す（上限: 直近のやり取りをトークン予算内で切り詰め）。
- **AL-205**: エラー時（API障害・レート制限・予算超過）は原因区分に応じた日本語メッセージをチャット内に表示し、入力欄は再送可能な状態を保つ。
- **AL-206**: 画像生成モデル選択時は、回答として生成画像（1枚〜複数枚）をチャット内に表示し、ダウンロードできる。生成画像はサーバー側ストレージに保存し履歴から再表示可能。
- **AL-210**: **ファイル添付**: 受講者が PDF・画像（PNG/JPEG/GIF/WebP）・テキスト（TXT/MD/CSV）を添付して質問できる。1件15MB・1通5件まで。添付はファイル選択時にアップロードし、送信時はIDのみを送る（大きなPDFでも送信操作が重くならないようにする）。
- **AL-211**: **添付の再送制御**: APIはステートレスなため過去の添付も毎回送り直すことになる。履歴全体で18MBを上限とし、超える場合は**古い添付から落として直近の資料を必ず残す**。落とした分はファイル名を本文に注記し、黙って消えないようにする。
- **AL-212**: **ファイル生成**: 受講者の依頼に応じて Excel(.xlsx)・Word(.docx)・PowerPoint(.pptx)・PDF を作成し、チャット内のリンクからダウンロードできる。生成物はサーバー側ストレージに保存し、履歴からも再取得できる。
- **AL-213**: **ファイル生成の可否設定**: 生成はコード実行を伴い従量課金が発生しうるため、会社ごとにオン/オフできる（既定オン）。無効の会社ではツール自体を付けない。
- **AL-214**: 対応外の形式・容量超過は、原因の分かる日本語メッセージを返す。
- **AL-215**: **画像生成の参照添付**: 画像生成モデルでも添付できる。会話中に添付された画像を参照として渡し（OpenAI `/v1/images/edits`）、デザインガイドのトンマナに合わせた画像を生成する。参照に使えるのは PNG / JPEG / WebP のみ（gpt-image の制約。GIF・PDF は不可）。枚数は新しいものから8件まで、合計24MBまで。テキスト添付（TXT/MD/CSV）はプロンプトへ差し込む。
- **AL-216**: **参照結果の可視化**: 何を参照したか・何が参照に使えなかったか（理由つき）を回答本文に残す。黙って無視すると「添付が効いていない」原因が受講者にも管理者にも分からなくなるため。

### 5.3 会話履歴（AL-3xx）

- **AL-301**: 左ペインに自分の会話一覧を新しい順に表示。クリックで会話を開く。「＋新しいチャット」で新規会話。
- **AL-302**: 会話タイトルは最初の質問文から自動生成（先頭30文字程度）。タイトルの手動リネーム可。
- **AL-303**: 会話の削除（論理削除・アーカイブ）が可能。削除した会話は本人には非表示、管理者の利用ログには残る。
- **AL-304**: 履歴は本人の分のみ表示（同じ会社の他の受講者の会話は見えない）。

### 5.4 モデル選択（AL-4xx）

- **AL-401**: チャット画面上部（またはプリセット選択と並置）で、以下のモデルから選択できる:

| 表示名 | プロバイダ | 実モデルID（初期値） | 種別 |
|---|---|---|---|
| Claude Fable | Anthropic | `claude-fable-5` | テキスト |
| Claude Opus | Anthropic | `claude-opus-5` | テキスト |
| Claude Sonnet | Anthropic | `claude-sonnet-5` | テキスト |
| Claude Haiku | Anthropic | `claude-haiku-4-5` | テキスト |
| ChatGPT（最新） | OpenAI | 環境変数 `OPENAI_CHAT_MODEL` で指定（既定 `gpt-5.6`） | テキスト |
| 画像生成 | OpenAI | 環境変数 `AILAB_IMAGE_MODEL` で指定（既定 `gpt-image-2`） | 画像 |

- **AL-402**: 実モデルIDはコード内カタログ＋環境変数で一元管理し、モデル改廃時に **設定変更のみ** で追従できる構造にする（受講者向け表示名は変えない）。
- **AL-403**: 会社ごとに **利用可能モデルのサブセット** と **既定モデル** を管理者が設定できる（例: 研修Aでは Claude Sonnet と画像生成のみ）。
- **AL-404**: モデルは会話の途中でも切り替え可能。メッセージごとに使用モデルを記録し、アシスタント発言の下に使用モデル名を小さく表示する。

### 5.5 プリセット（システムプロンプト＋アセット）（AL-5xx）

- **AL-501**: 管理者は会社ごとに複数の **プリセット** を登録できる。プリセット = 表示名・説明・システムプロンプト・（任意）モデル固定・参照アセット群。
- **AL-502**: 受講者は新規会話の開始時にプリセットを選択できる（「標準（プリセットなし）」を含む）。会話単位で固定され、途中変更は不可。
- **AL-503**: **アセット** はテキストまたはファイル（PDF / Markdown / テキスト、上限10MB）。ファイルはアップロード時にテキスト抽出し、システムプロンプトに続けて注入する（合計注入上限あり、超過分は末尾切り詰め＋管理画面に警告表示）。
- **AL-504**: システムプロンプト・アセットの内容は受講者には表示しない（プリセット名と説明のみ見える）。
- **AL-505**: プリセットにモデル固定が設定されている場合、その会話ではモデル選択UIを固定表示にする。
- **AL-506**: 全社共通の **ベースガードレール**（研修用途・個人情報入力への注意・悪用防止の指示文）を全リクエストのシステムプロンプト先頭に必ず結合する（管理者プリセットでも上書き不可）。

### 5.6 管理画面（CRM内）（AL-6xx）

- **AL-601**: CRM の管理者（`owner` / `admin`）のみが `/app/ai-lab` にアクセスできる（既存 `requireAdminCtx` に準拠）。
- **AL-602**: **会社管理**: 登録（名称・スラッグ・Basic認証ID/パスワード・利用可能モデル・既定モデル・月間トークン予算・有効期間）・編集・無効化。CRM の `accounts`（取引先）への任意リンク。
- **AL-603**: **利用者管理**: 個別追加＋CSV/複数行一括発行（ログインID・表示名・初期パスワード自動生成）。パスワード再発行・無効化・ロック解除。発行結果は接続情報（URL/Basic/個別ID・初期PW）としてコピー可能な形で表示（保存はハッシュのみ、平文はこの画面表示限り）。
- **AL-604**: **プリセット/アセット管理**: プリセットCRUD、アセットのアップロード・差し替え・削除、注入テキストのプレビューと注入量（概算トークン）表示。
- **AL-605**: **利用状況**: 会社別・利用者別・モデル別の集計（リクエスト数 / 入出力トークン / 画像枚数）と概算コスト表示。会話・メッセージの閲覧（研修振り返り用途。監査目的でメッセージ本文を管理者が閲覧できる旨は顧客向け案内に明記する）。
- **AL-607**: **月別推移（会社単位）**: 会社の利用状況タブに直近12か月の推移を表示する。棒グラフ＝入出力トークンの積み上げ（左軸）、折れ線＝概算コスト（右軸）。月別の明細表（リクエスト / 入力・出力・合計トークン / 画像 / 概算コスト / 予算消化率）と、当月の前月比を併記する。利用の無い月もゼロとして残し、横軸が歯抜けにならないようにする。
- **AL-608**: **月別レポート（会社横断）**: `/app/ai-lab/reports` に全社の月別推移を表示する。対象月を選ぶと、その月の会社別内訳（リクエスト / 合計トークン / 画像 / 概算コスト / 予算消化率）とモデル別内訳が切り替わる。会社 × 月のマトリクス表で直近12か月を一覧でき、予算未設定の会社からは設定画面への導線を出す。
- **AL-609**: **概算コストの単価**: モデルカタログに定価ベースの標準単価を内蔵し、環境変数なしでもコストを表示する。`AILAB_PRICES` で実勢価格に上書きできる。単価を持たない利用（画像生成など）が含まれる場合は、概算が実額を下回る旨を画面に注記する。
- **AL-606**: **プレビュー導線**: 会社詳細から「体験環境を開く」で `/lab/{slug}` を新規タブで開く。管理者向けにBasic認証・個別ログインを省略できる **署名付きプレビューリンク**（有効60秒・ワンタイム）を発行できる。

### 5.7 CRMからの動線（AL-7xx）

- **AL-701**: CRM サイドバーの「顧客」グループ（管理者のみ）に「AI体験環境」を追加し `/app/ai-lab` へ遷移できる（`nav-config.ts` 準拠）。
- **AL-702**: `accounts`（取引先）詳細画面に、リンク済み AI Lab 会社がある場合「AI体験環境」バッジ＋ジャンプリンクを表示する。
- **AL-703**: 顧客向け動線は **会社別URLの直接アクセスのみ**（AL-101/102）。CRM側からの遷移はあくまで当社スタッフ用。

### 5.8 利用制限・記録（AL-8xx）

- **AL-801**: 会社ごとの **月間トークン予算**（入出力合算）を設定できる。超過後は当月中チャット送信をブロックし、「利用上限に達しました。担当者にお問い合わせください」を表示。管理画面では80%到達時に警告表示。
- **AL-802**: 利用者ごとの **レート制限**: 直近1分あたり送信10回・画像生成は1分3回まで。超過時は待機を促すメッセージ。
- **AL-803**: 全メッセージ（入力・出力・使用モデル・トークン数・エラー）をDBに記録する。保持期間は契約終了後1年（以後、運用で削除）。
- **AL-804**: ログイン成功/失敗・ロック・管理操作（会社/利用者/プリセットの作成・変更）は既存の監査ログ方針に準じて記録する。

## 6. 非機能要件

| 区分 | 要件 |
|---|---|
| 性能 | 初回描画 2秒以内（会話20件・メッセージ50件時）。チャット応答はストリーミング開始まで 3秒以内（プロバイダ遅延除く） |
| 可用性 | CRM本体と同一（Vercel + Supabase）。AIプロバイダ障害時もアプリ自体は継続動作し、エラーを明示 |
| セキュリティ | 会社間・利用者間のデータ分離（アプリ層 + RLS の二重防御）。パスワードは bcrypt、Basic認証秘密はハッシュ保存。セッションはHMAC署名Cookie。CSRF はServer Actions/同一オリジンPOSTに限定。AIへの入力に CRM 内部データを一切含めない |
| プライバシー | 受講者入力は学習に使用されないAPIプラン前提。管理者がメッセージを閲覧できる旨を利用案内に明記 |
| 監視 | Sentry（既存）にエラー送信。AIプロバイダ課金の急増をチェックできる利用集計（AL-605） |
| 運用 | モデル改廃は環境変数/カタログ変更のみで対応。会社追加〜受講者発行が管理画面のみで完結（エンジニア作業ゼロ） |

## 7. 制約・前提

- 実装は既存リポジトリ内（同一 Next.js アプリ・同一 Vercel プロジェクト・同一 Supabase）。ドメイン分離はせず、パス `/lab` で分離する（判断根拠はシステム化要件書 §2）。
- 必要APIキー: `ANTHROPIC_API_KEY`（設定済み）、`OPENAI_API_KEY`（.env.example 定義済み・本番未設定なら要発行）、画像生成用キー（§8-1 の決定後）。
- Basic認証はブラウザ標準ダイアログを利用（デザイン不可）。「環境への一次ゲート」であり、本人認証は個別ログインが担う。

## 8. 決定事項・未確定事項

1. **画像生成モデル（決定済）** — OpenAI の **`gpt-image-2`**（Images API）を使用する。当初「Imagen 2」と記載されていたが、確認の結果 OpenAI の gpt-image-2 を指すものと確定した。実モデルIDは `AILAB_IMAGE_MODEL` で差し替え可能とし、将来別プロバイダに切り替える場合に備えて `ImageProvider` 抽象を挟む（詳細設計 §6）。
2. **「ChatGPT の最新モデル」の追従方針（未確定）** — 環境変数 `OPENAI_CHAT_MODEL` で指定する。初期値と、モデル改定時の追従タイミング（都度手動更新でよいか）を要確認。
3. **月間トークン予算の既定値（未確定）** と超過時の扱い（v1 はブロック。「管理者へ通知して継続」オプションが要るか）。
4. **契約終了時のデータ扱い（未確定）**（無効化のみ / 一定期間後削除）。v1 は無効化のみ実装し、削除は運用手順とする。
