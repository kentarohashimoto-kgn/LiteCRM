# CATORCE Sales OS オンボーディング資料

**対象**：新しく参加する営業担当者・バックオフィス担当者
**所要**：通読 20分 ／ 初期セットアップ 30分 ／ 定着まで 2週間

> 操作の詳細は別紙 **[MANUAL.md（マニュアル）](./MANUAL.md)** を参照してください。
> 本資料は「なぜ使うのか・どう活かすのか・何を守るのか」を扱います。

---

## 1. 背景 — なぜこのシステムがあるのか

### 1-1. 解決したかった課題

以前は商談情報がNotion・スプレッドシート・個人の頭の中に分散していました。その結果：

| 起きていたこと | 何が問題か |
|---|---|
| 案件の最新状況が担当者に聞かないと分からない | 会議が「報告会」になり、対策を打つ時間が残らない |
| 月末にならないと着地見込みが分からない | 手遅れになってから気づく。打ち手が間に合わない |
| 「なぜ勝ったか・負けたか」が残らない | 勝ち筋が個人に閉じ、組織の型にならない |
| 提案後のフォロー漏れ・放置案件 | 取れたはずの案件を落とす |
| 受注後の原価・稼働が見えない | 売れているのに利益が残らない。人員手配が後手に回る |

### 1-2. コンセプト

> **営業活動を「記録するだけ」のCRMから、「未来の売上を作る」営業OSへ。**

このシステムは**入力させるための管理ツールではなく、意思決定のための道具**です。
入力されたデータは必ず、次の判断（誰に・いつ・何をするか）に還元されます。

## 2. 目的 — このシステムで実現すること

### 2-1. 3つのゴール

1. **今月の着地を、月初に分かるようにする**
   ヨミ（確度）× 金額で加重した予測を常に最新化し、目標とのギャップを可視化する。
2. **打ち手を早く・具体的に決める**
   放置案件・フォロー漏れ・停滞案件を自動検知し、週次レビューで対策まで決める。
3. **売れて、かつ利益が残る状態をつくる**
   受注後のデリバリー原価・稼働・継続見込みまで管理し、採用/契約の判断を前倒しする。

### 2-2. 売上を分解して考える（共通言語）

このシステムは、売上を次の掛け算として捉えています（**営業レントゲン**画面の考え方）。

```
売上 = リード数 × アポ獲得率 × 商談実施率 × 受注率 × 平均単価
```

数字が落ちたとき「気合いが足りない」ではなく、**どの因数が悪化したか**を特定し、
そこに効く打ち手を選びます。この分解が全社の共通言語です。

## 3. 全体像 — データの構造を理解する

### 3-1. 3階層モデル

すべての営業データはこの3階層に乗ります。ここだけは必ず覚えてください。

```
顧客（会社）
  └─ 案件（その会社との取引1件。金額・ヨミ・担当を持つ）
       └─ 商談 / 活動（訪問・電話・メール等の記録）
```

- **顧客**＝会社。同じ会社を二重に作らない（重複は名寄せの手間になります）
- **案件**＝「〇〇社／AI研修」のような取引単位。**売上予測の最小単位**
- **活動**＝やったこと。**次アクションとセットで記録**する

さらにその手前に **リード**（展示会・セミナーで獲得した見込み客リスト）があり、
アポが取れた時点で「顧客＋案件」に昇格します。

### 3-2. ヨミ（最重要）

**ヨミ**は案件の確からしさを表す全社共通の物差しです。**ヨミを正しく入れることが、
このシステムを使ううえで最も重要な仕事**です。

| ヨミ | 意味 | 確度 |
|---|---|---|
| `0.受注` | 受注確定 | 100% |
| `1.A(80%)` | ほぼ確実。社内検討・稟議中 | 80% |
| `2.B(50%)` | 有望。提案済み | 50% |
| `3.C(30%)` | 商談実施済み。継続協議 | 30% |
| `4.アポ` | アポ獲得済み・初回商談待ち | 20% |
| `5.リスケ` | 日程延期 | 10% |
| `6.定期追い` | 中長期フォロー対象 | 10% |
| `7.オチ` | 失注 | 0% |
| `8.キャンセル` | 案件消滅 | 0% |
| `9.調整中` | 日程調整中 | 15% |

> **ヨミを変えると、ステージ・確度・ステータスが自動で連動します。**
> 担当者が触るのはヨミだけでOK。ステージを個別に管理する必要はありません。

**売上予測はこの式で計算されます：**

```
Weighted（加重見込み）= 案件金額 × 確度
```

つまり **ヨミが実態とズレていると、会社全体の着地予測がズレます**。
「行けそうな気がする」でAにせず、事実（誰が・何を・いつまでに決めるか）で判断してください。

### 3-3. 年度の考え方

カトルセは **決算6月＝7月始まり** です。
「FY2026」は **2026年7月〜2027年6月** を指します。目標入力・売上予測はこの区切りです。

## 4. あなたの役割と見える範囲

ロールによって表示されるメニューとデータ範囲が変わります（DBレベルで制御）。

| ロール | 主な役割 | 見える範囲 |
|---|---|---|
| 代表(Owner) / 管理者 | 全社統括・設定 | 全て |
| Sales Ops | 全案件のレビュー・分析 | 営業データ全て |
| **営業担当** | 案件を進める | **自分の担当案件** |
| 外部営業 / パートナー | 割当・紹介案件を進める | 割り当てられた案件のみ |
| 講師/PM | 受注後のデリバリー | 受注後案件・顧客情報 |
| 経理 | 契約・請求 | 契約・請求関連 |
| **事務(バックオフィス)** | 納期のある事務作業 | **BO領域のみ（営業データは不可視）** |
| 人事 | 採用・人材台帳 | BO領域＋タレント |
| 閲覧者 | 閲覧のみ | 閲覧のみ |

> **営業とバックオフィスは相互に不可視**です。BO担当の方に営業メニューが見えないのは
> 仕様であり、故障ではありません。

## 5. 活用法 — 業務リズムに組み込む

システムは「思い出したときに開く」のでは機能しません。**次のリズムで習慣化**してください。

### 5-1. 営業担当のリズム

#### 毎日（合計10分）

| タイミング | やること | 画面 |
|---|---|---|
| 朝 | 今日のアポと次アクションを確認 | **今日のアポ・AC** |
| **商談直後（5分以内）** | **活動を記録し、次アクションを必ず入れる** | 今日のアポ・AC / 活動を登録 |
| 夕方 | ヨミが変わった案件を更新 | 案件（表・ボード） |

> 💡 **商談後5分ルール**：移動中でも構いません。記憶が新しいうちに書くのが最も速く、
> 最も正確です。「あとでまとめて」は必ず抜けます。

#### 毎週

| タイミング | やること | 画面 |
|---|---|---|
| 週初 | 自分の週報を記入（先週の差分・今週の予定） | **営業マン別週報** |
| 週次会議 | 打ち手を決める（報告ではなく意思決定） | **週次レビュー** |
| 週末 | 稼働実績を提出（デリバリー担当のみ） | 稼働報告 |

#### 毎月

| タイミング | やること | 画面 |
|---|---|---|
| 月初 | 当月の目標と着地見込みのギャップを確認 | ダッシュボード / 売上予測 |
| 月中 | ヨミの棚卸し（古いヨミを実態に合わせる） | 案件（表・ボード） |
| 月末 | 決着（受注・オチ）の理由を記入 | ヨミ変更履歴 |

### 5-2. バックオフィス担当のリズム

| タイミング | やること | 画面 |
|---|---|---|
| 毎日 | 期日が近い事務作業を確認 | **BOダッシュボード** |
| 研修受注時 | 助成金の期日を登録（事前申請＝研修1ヶ月前） | 助成金トラッカー |
| 展示会確定時 | WBSを自動生成し、準備タスクを進める | 展示会準備WBS |
| 研修実施後 | 1・3・6ヶ月後フォローの日程調整 | 研修後フォロー |
| 随時 | 講師スケジュール調整・アンケート取込・事例化 | AI講師スケジュール ほか |

> BO業務の共通点は **「納期がある」** ことです。BOダッシュボードで期日を横断的に
> 見張るのが基本動作になります。

### 5-3. AIによる自動処理

以下は**あなたが操作しなくても自動で動きます**（結果の確認だけお願いします）。

| 自動処理 | タイミング | あなたがすること |
|---|---|---|
| 商談AI要約の下書き作成 | 夜間 | **AI確認キュー**で内容を確認し「確認済み」に |
| 日次ダイジェスト通知 | 毎朝 | 通知を見て当日の動きを決める |
| ワークフロー自動化（ヨミ転落→通知等） | 30分ごと | ルールに沿った通知に反応する |
| メールシーケンス（多段フォロー） | 毎日 | 投入した案件の自動送信結果を確認 |
| 営業レントゲンのスナップショット保存 | 毎月1日 | 前月との比較を見る |

> ⚠️ AIの要約は**下書き**です。事実確認をせずに確認済みにしないでください。

## 6. 運用ルール（全員が守ること）

品質はルールの遵守で決まります。以下は**チームの約束**です。

### 6-1. 必ず守る5原則

1. **商談後5分以内に活動を記録する**
   → 記録がない商談は「無かったこと」になります。

2. **次アクション（日付＋内容）を必ず設定する**
   → 未設定の案件は自動で「危険案件」として検知されます。

3. **ヨミは事実で判断し、常に最新に保つ**
   → 願望でAにしない。動きがなければ落とす勇気を持つ。

4. **受注・オチに変更したら、必ず理由を記入する**
   → 成約分析・失注分析の元データになります。ここが空だと組織に学びが残りません。

5. **顧客・案件を二重に作らない**
   → 登録前に必ず検索する。同名があれば既存を使う。

### 6-2. 自動検知される「危険案件」

以下は放置するとシステムが自動で警告します。

| 検知 | 条件 |
|---|---|
| 放置案件 | 最終活動から **7日以上** 動きがない |
| 提案後フォロー漏れ | 提案から **7日以上** フォローがない |
| 次アクション未設定 | 次アクションが空 |

### 6-3. 入力の粒度ガイド

| 項目 | ルール |
|---|---|
| 顧客名 | 正式名称（株式会社を含む）。略称・部署名を混ぜない |
| 案件名 | `顧客名 / 商材` を基本形にする（例：`日本トムソン株式会社 / AI研修`） |
| 金額 | **税抜**で統一。入力欄は自動で3桁カンマ表示されます |
| 受注予定日 | 「いつ決まるか」の想定日。月次集計の基準になるので必ず入れる |
| 活動メモ | 誰が・何を言ったか（事実）と、次に何をするか（判断）を分けて書く |

### 6-4. やってはいけないこと

- ❌ ヨミを更新せずに放置する（着地予測が壊れます）
- ❌ 失注案件を消す（**オチとして残す**。分析の元データです）
- ❌ 個人メモに商談内容を溜める（組織資産になりません）
- ❌ 顧客名を都度書き換える（重複・名寄せの原因になります）

## 7. 最初の1週間でやること（チェックリスト）

## 8. よくある質問

**Q. 入力が面倒です。どこまで入れればいいですか？**
A. 最低限は **①ヨミ ②金額 ③次アクション（日付＋内容） ④活動記録** の4点です。
ここさえ埋まれば、予測・検知・分析はすべて動きます。

**Q. ヨミの判断に迷います。**
A. 「**次に何が起きれば前に進むか**」が言えるならC以上、言えないなら定期追いです。
Aは「決裁が通る見込みが立っている」状態に限定してください。

**Q. 間違えて削除しました。**
A. リード・案件・顧客は **ゴミ箱に30日間**保管されます（設定 → ゴミ箱）。復元できます。

**Q. 同じ会社が2つ登録されています。**
A. **設定 → 重複の検出とマージ**で統合できます。関連データは残す側に付け替わります。

**Q. 自分に見えない画面があります。**
A. ロールによる制御です（4章参照）。業務上必要であれば管理者に相談してください。

**Q. AIの要約が間違っています。**
A. AI確認キューで修正してから確認済みにしてください。修正内容が正データになります。
