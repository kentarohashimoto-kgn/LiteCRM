# WO-07: AI営業支援機能

> 前提: WO-01/02/04完了。**ユーザー側で `ANTHROPIC_API_KEY` をVercel環境変数に登録済みであること（未登録なら着手前に依頼して待つ）**。要件書6章対応。
> **目的**: 商談準備・議事録整理・アップセル発案・フォロー文面・会議準備をAIで底上げし、営業品質の属人性を下げる。

## 共通基盤（最初に作る）

### `src/server/ai.ts`
- `@anthropic-ai/sdk` を依存に追加（今回唯一の新規依存。それ以外の依存追加は禁止）。
- モデル: `claude-sonnet-5` 固定。`max_tokens: 2500`。temperature低め(0.3)。
- **サーバー専用**（"use server"のactionから呼ぶ。クライアントへAPIキーが漏れない構成をビルドで確認）。
- 共通関数 `runAiTask(taskKind, systemPrompt, userContent): Promise<string>`:
  - APIキー未設定時は「AI機能は未設定です（管理者にお問い合わせください）」を返す（throwしない）。
  - エラー時も日本語メッセージ返却。呼び出しは**明示ボタンのみ**（自動実行・バックグラウンド実行禁止 = コスト管理）。
- 監査: `ai_runs` テーブル（migration 0050: id/tenant_id/user_id/task_kind/input_chars/output_chars/created_at、RLS4点）に1行記録。**プロンプト本文は保存しない**（PII最小化）。

### プロンプト設計の共通原則
- systemに「株式会社カトルセ（生成AI研修/AI顧問/SUISHIN/Dify・RAG開発/eラーニング）の営業支援AI」という前提と、**出力フォーマット（見出し付き日本語）**を固定。
- 入力データはDBから組み立てる（solution_packages / sales_templates / 活動履歴 / 案件情報）。**ユーザーが貼るのは議事録テキスト程度**。

## 5機能（要件書6.1〜6.6。6.4リードスコアはWO-06のルールベースで充足済みのため対象外）

| 機能 | 置き場所 | 入力（自動収集） | 出力 |
|---|---|---|---|
| 6.1 商談前リサーチ | 案件詳細・リード詳細「AI準備」ボタン | 会社名/URL/業種/部署/役職/ソース/関心 + 業種職種テンプレ + パッケージ一覧 | 企業概要仮説/業界課題/AI活用テーマ/初回質問リスト/提案候補/トーク案 ※Web検索はしない=保有情報からの仮説と明記 |
| 6.2 議事録要約 | 活動登録フォーム・活動詳細「AI要約」 | 貼り付けた議事録/tl;dv文字起こし + 案件文脈 | 課題/重要発言/予算/決裁者/時期/提案余地/次回AC案/確度案/本部論点 → **ワンクリックで activities の各フィールド（発掘課題・反応・次回AC等）へ反映** |
| 6.3 アップセル提案 | アカウントプラン・顧客詳細「AI提案」 | 顧客情報/過去納品/活動履歴/未解決課題/パッケージ一覧 | 次提案商品候補(パッケージ名で)/お土産提案文/アポ打診メール/提案骨子/想定ROI/本部相談点 |
| 6.5 フォロー文面 | 案件詳細「AIメール文面」 | 案件/最新活動/分類/パッケージ | 御礼/提案送付/追加事例/再フォロー/御用聞き/お土産提案 の6種から選択生成 → コピー用表示 |
| 6.6 会議アジェンダ | 本部ダッシュボード「今週の会議アジェンダ生成」 | sales_alerts結果 + A/B案件 + 超過AC + 接触漏れ + 担当別実績（すべて既存RPCから） | 確認すべき案件/超過案件/支援要請案件/担当別指摘/アジェンダ |

- 生成結果は基本「表示+コピー」。6.2のみ構造化反映（JSONで返させ、フィールドへ流し込み。ユーザーが確認してから保存）。
- 生成結果の保存: 6.2は activities.ai_summary へ、他は必要ならメモ欄に手動コピー（自動保存しない）。
