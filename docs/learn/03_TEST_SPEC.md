# CATORCE Learn テスト仕様書 v1.0

作成: 2026-07-25 ｜ 対応: `01_REQUIREMENTS.md`（FR/NFR）・`02_DETAILED_DESIGN.md`

## 1. テスト方針

| レイヤ | ツール | 対象 |
|---|---|---|
| ユニット | Vitest | can_view判定、ID上限計算、集計ロジック、ドメイン検証 |
| DB/RLS | SQLテスト（supabase test / pgTAP） | 全RLSポリシーのクロステナント遮断、view_events追記専用 |
| API結合 | Vitest + supertest（route handlers） | A-01〜A-10の正常系/異常系 |
| E2E | Playwright（環境のChromium使用） | 招待→視聴→ログ→CSVの主要フロー |
| 受入(UAT) | 手動シナリオ | パイロット2社オンボーディング |

- テストデータ: 2テナント（T1=light 50ID・契約中／T2=archive 30ID・契約終了済み）＋共通コース(light)・T1限定アーカイブコースを標準フィクスチャとする
- **リリース判定: TC-SEC群およびTC-LOG群が全PASSであることを必須条件とする**（要件書§7）

## 2. テストケース

## 3. 受入テスト（UAT）シナリオ — 和光紙器オンボーディング想定

1. 運営がテナント作成（plan=archive・30ID・契約1年・許可ドメイン `wakosiki.co.jp`）し、研修アーカイブコース（動画10本・標準学習時間600分）をテナント限定で公開
2. tenant_admin（本橋様想定）を招待→受諾→learner 8名を招待
3. learner 3名が視聴（うち1名は途中まで）→ tenant_adminが視聴マトリクスとCSVで学習時間を確認
4. 運営が「特典: gift_light 3ヶ月」を発行→Light共通コースが見えるようになることを確認
5. 契約終了日を昨日に変更→cron実行→全learnerの再生が403になり、案内文言が表示される
6. 助成金想定: 受講者×期間×学習時間のCSVが申請添付様式として成立しているか営業/社労士がレビュー

## 4. 障害時の退避基準

- TC-SEC群に1件でもFAILがある場合はリリース禁止（例外なし）
- TC-LOG群のFAILは助成金訴求の停止（「助成金対応」を外して限定ローンチは可）と経営判断へエスカレーション
