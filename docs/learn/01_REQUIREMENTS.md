# CATORCE Learn 要件定義書 v1.0

作成: 2026-07-25 ｜ 前提資料: `docs/CATORCE_LEARN_HANDOFF.md`（商品仕様・価格は同書が正、本書で再定義しない）

## 1. 背景・目的

- カトルセのストック収益戦略の中核となる自社eラーニング基盤を、**Vercel + Supabase** で構築する
- UTAGE（月2.5万）・パートナープロップ（月20万）を段階的に置き換え解約する
- 人材開発支援助成金「定額制訓練」の対象要件を満たし、「助成金対応eラーニング」を営業上の武器にする
- 将来のAIチャットボット（動画内容RAG）と外販を見据えた設計とする

## 2. スコープ

| フェーズ | 期限目標 | 内容 |
|---|---|---|
| **MVP** | 2026年11月着手 → **2027年1月 アカデミーLightローンチ** | 配信・視聴ログ・テナント管理・2種の管理画面 |
| Phase 2 | 2027年Q1〜 | レポート自動生成・修了証・診断・LiteCRM連携・助成金レポート |
| Phase 3 | 来期 | RAGチャットボット・外販（セルフオンボーディング＋Stripe課金） |

**スコープ外（MVP時点)**: 決済（請求は既存の請求書運用）、SCORM、モバイルアプリ、パートナープロップの代理店ポータル機能。

## 3. 利用者・ロール

| ロール | 説明 | 主な画面 |
|---|---|---|
| `catorce_admin` | カトルセ運営者 | 運営管理画面（テナント・コンテンツ・特典） |
| `tenant_admin` | 顧客企業の管理者 | 顧客管理画面（メンバー招待・視聴状況） |
| `learner` | 受講者（記名ID） | 学習者ポータル |

- 1ユーザーは必ず1テナントに所属（カトルセ運営者を除く）
- **IDは記名式**。共有アカウントは規約で禁止（助成金要件）

## 4. 機能要件

### MVP

| ID | 要件 | 詳細 |
|---|---|---|
| FR-01 | テナント管理 | プラン（archive/light/pro）、ID上限バンド、契約期間、ステータス、LiteCRM企業IDとの紐付けキーを管理 |
| FR-02 | 記名ID招待 | メール招待制。**テナントに登録された許可ドメインのみ**受諾可能。招待の有効期限あり |
| FR-03 | 認証 | Supabase Auth（メールリンク＋パスワード）。セッションはテナント・ロールを持つ |
| FR-04 | コース/レッスン管理 | コース＞レッスンの2階層。コースに**標準学習時間**（助成金要件）・対象プランTier・タグ（ツール名/レベル/公開日）を持つ。アーカイブ用コースは特定テナント限定公開ができる |
| FR-05 | 動画アップロード | Cloudflare Streamへのダイレクトアップロード。エンコード完了をWebhookで受けてレッスンに紐付け |
| FR-06 | 動画再生 | 署名付きトークンでの再生のみ許可（TTL 2時間）。ダウンロード抑止。再生可否は「テナント契約が有効 × プランTierがコースTier以上 × （テナント限定コースなら自テナント）」で判定 |
| FR-07 | 視聴ログ | 再生中10秒間隔のハートビートで視聴イベントを記録し、レッスンごとの進捗（最大到達位置・累計視聴秒・完了）に集計。**ログは追記専用**（助成金証憑） |
| FR-08 | 学習者ポータル | コース一覧（自分のプランで見られるもの）、続きから再生、視聴履歴、学習時間の自己確認 |
| FR-09 | 顧客管理者画面 | メンバー招待/無効化、利用中ID数/上限の表示、メンバー別・コース別の視聴状況一覧、CSVダウンロード |
| FR-10 | 運営管理画面 | テナントCRUD、コース/レッスンCRUD、**特典発行**（例: アーカイブ1年無償。期限付きエンタイトルメント）、全テナント横断の利用状況 |
| FR-11 | 自動アクセス停止 | 契約終了日・特典期限の翌日0時に該当テナント/エンタイトルメントの再生を自動停止（日次バッチ＋再生時判定の二重化） |
| FR-12 | ID上限制御 | アクティブID数が契約バンド上限に達したら招待をブロックし、管理者に上限変更の案内を表示 |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | **マルチテナント分離**: 全テーブルに `tenant_id`＋Supabase RLS。クロステナントの読み書きはDB層で不可能にする（アプリ層の判定に依存しない） |
| NFR-02 | 再生URLは署名付き・TTL 2時間・ユーザー単位。直リンク・共有リンクでの視聴不可 |
| NFR-03 | 性能: 再生開始まで3秒以内、主要ページ表示1.5秒以内（LCP） |
| NFR-04 | 可用性99.5%目標。Supabase日次バックアップ＋PITR。Cloudflare Stream側に動画原本 |
| NFR-05 | 視聴イベントは追記専用（UPDATE/DELETE不可のRLS）。集計テーブルと突合可能にし助成金監査に耐える |
| NFR-06 | 個人情報は氏名・メール・所属部門のみ保持。退職者の無効化と削除要求への対応手順を持つ |
| NFR-07 | 変動費はStream従量＋Vercel/Supabaseのみ。**ユーザー数比例のSaaS費用を発生させない**（1テナント原価は月数百円台を維持） |
| NFR-08 | 助成金要件準拠: 記名ID・視聴ログ・標準学習時間・修了管理・実績レポート（詳細はHANDOFF §3。社労士確認結果を随時反映） |
| NFR-09 | 文字起こしはMVP時点から全動画で生成・保存（Phase 3のRAGコーパス。後付け禁止） |

## 6. 制約・技術前提

- スタック: Next.js 14 (App Router) / TypeScript / Tailwind / Supabase (Postgres, Auth, Storage) / Vercel / Cloudflare Stream — LiteCRMと同一系統に統一
- リポジトリはLiteCRMとは別に新設（`catorce-learn`）。テナントはLiteCRMの `accounts.id` を参照キーとして保持
- 請求・契約管理の金額情報はMVPではLiteCRM側（billing_schedules）が正。Learnは「アクセス制御に必要な契約情報」だけを持つ

## 7. 受入基準（MVPローンチ判定・2027年1月）

1. パイロット2テナント（うち1社は和光紙器想定）で招待→視聴→ログ集計→CSV出力が一連で動作
2. クロステナントアクセスがRLSテストで全パターン遮断されている（テスト仕様書 TC-SEC 群が全PASS）
3. 契約終了・特典期限の自動停止が日次バッチで動作
4. アーカイブ動画10本＋Light初期コンテンツ（月4本×2ヶ月分）が搭載済み・文字起こし付き
5. 視聴ログの集計値が手動計測と±5%以内で一致
