# 01. 顧客ベネフィットの定義

## ターゲット顧客（優先順）

### 第1ターゲット: 中小企業の経営者・役員（非エンジニア）
- 従業員5〜50名。営業管理をExcel・スプレッドシート・記憶で回している
- Salesforce等を検討したが「高い・複雑・自社に合わない・使いこなせる気がしない」で断念、
  もしくは導入したが定着せず解約した経験がある
- ChatGPTは触ったことがあるが「業務システムをAIで作れる」とは思っていない。
  あるいは「AIで作れるらしいが、危なくないのか」が不安で踏み出せていない

### 第2ターゲット: 営業部門の責任者・DX担当者
- 経営層から「AIで何かやれ」と言われているが、何から手を付けるべきか分からない
- 現場のツール不満（入力が面倒・欲しいレポートが出ない・ツールが多すぎて
  情報が散らばる）を解決する武器が欲しい

### 第3ターゲット: 士業・コンサル・制作会社など「顧客に提案する側」
- 本ノウハウを自分の顧客への提供メニューに転用したい層（単価が高く決断が速い）

## 顧客の痛み（Before）

| 痛み | 現状の姿 |
|---|---|
| 時間がない | 平日は商談・面談・会食、土日は資料づくりで消える。改善に割く時間が捻出できない |
| SaaSが合わない | 月額を払い続けても自社の営業フローに合わず、結局Excel併用 |
| ツールがバラバラ | SFA・タスク管理・マインドマップ・分析…契約が増え、月額もデータも分散 |
| 開発は高すぎる | 受託見積は300万円〜、仕様変更のたびに追加費用と数週間の待ち |
| AIが怖い | 「AIで作れる」と聞くが、情報漏えいやデータ消失が不安で任せられない |
| 営業が属人化 | ヨミも次アクションも担当者の頭の中。会議は「確認」で終わる |

## 提供する変化（After）

**機能の説明ではなく「顧客の状態変化」で定義する。5つの柱に対応させる。**

1. **作る側に回れる（バイブコーディングの有益性）** — 外注も高額SaaSもなしに、
   自社専用の営業システムをAIとの対話で立ち上げ、翌日から自分で改修できる状態になる。
   「何となく不便」をAIに伝わる要件へ翻訳するスキルは、CRM以外の全業務に転用できる
2. **安全に作れる（リスク対策込み）** — 「動くけど危ない」を避けられる。
   認証・権限・バックアップ・情報の扱いまで、社員に使わせてよい水準の作り方と、
   バイブコーディング特有の落とし穴（AIの暴走的な変更・壊れる修正・
   セキュリティの見落とし）の防ぎ方を最初から知った状態でスタートできる
3. **多機能なCRM/SFAが安価に手に入る** — 商談管理・ヨミ管理・売上予測・週次レビュー・
   危険案件検知・リード管理・一括メール・SEO分析…35超の機能を、
   インフラ費月数千円で。機能追加は「AIに頼む」だけで、追加費用の見積は来ない
4. **今使っているツールとつながる** — Gmail・Googleカレンダー・Google Chat・
   Search Console・自社HPの問い合わせフォーム。日々の仕事の流れの中にCRMが入り、
   「入力のための入力」が減る
5. **ツールの契約を減らせる** — タスク管理（Asana的機能）・マインドマップ・案件管理・
   原価管理・営業分析が1つに集約。バラバラの月額課金と、ツールをまたぐ
   二重入力・転記が消える。データが1箇所にあるから分析もつながる

## ベネフィットの一言化（エレベーターピッチ）

> 「20年以上コードを書いていない、平日に時間のない経営者が、週末の夜だけで
> 自社専用CRM/SFAを本番稼働させ、8週間・526コミットで多機能に育てた
> 全記録と再現手順。危ない作り方と安全な作り方の違いまで含めて渡します。
> 買うのはツールではなく、**"自社の業務システムを安全に作り続けられる能力"** です。」

## 機能→ベネフィット変換表（LP・営業トークで使う）

| 商品に含まれるもの（Feature） | 顧客ベネフィット（Benefit） |
|---|---|
| 実プロジェクトの全開発記録（8週間・526コミット分の意思決定） | 何をどの順番で作ればいいか迷わない。失敗を先回りで回避できる |
| バイブコーディングのリスク解説＋安全チェックリスト | 「動くけど危ない」を作らない。社員・顧客データを守りながら進められる |
| プロンプト・指示の実例集 | AIへの「正しい頼み方」を真似するだけで再現できる |
| 要件定義・設計書テンプレート | 自社の営業フローを書き込むだけでAIに渡せる仕様書が完成する |
| 35超の機能の実装記録（商談〜SEO分析まで） | 「ここまで作れる」の全体像が見え、自社に必要な分だけ選んで作れる |
| Gmail・カレンダー・Chat等の連携手順 | 既存の仕事の流れを変えずにCRMを差し込める |
| タスク・マインドマップ・原価管理等の置き換え実例 | 月額課金ツールを減らし、データを1箇所に集められる |
| 週次レビュー・ヨミ管理の営業メソッド | システムと同時に営業マネジメントの型が導入できる |
| 無償アップデート（章・テンプレ・事例追加） | 買った後も価値が増え続ける。陳腐化しない |

## 訴求しないこと（誠実さの線引き）

- 「誰でも1日でできる」とは言わない → 「経営者の本気の1〜2週間」と正直に言う
- 書き手を「プログラミング未経験」とは言わない → 20代の開発経験（20年以上のブランク）と、
  自社開発チームの手順という下地があったことを開示する。その上で
  「下地そのものを教材化したので、持たない人はこれを借りればよい」と訴求する
- 「AIに任せれば安全」とは言わない → リスクは実在する。だからこそ
  「リスクを知って対策した上で作る」ことを商品の核に据える
- 「エンジニア不要で何でも作れる」とは言わない → 適用範囲と限界（大規模・
  ミッションクリティカル領域は専門家併用）を明示する。この誠実さが10万円の信頼を作る
