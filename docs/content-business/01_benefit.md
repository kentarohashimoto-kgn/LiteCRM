# 01. 顧客ベネフィットの定義

## ターゲット顧客（優先順）

### 第1ターゲット: 中小企業の経営者・役員（非エンジニア）
- 従業員5〜50名。営業管理をExcel・スプレッドシート・記憶で回している
- Salesforce等を検討したが「高い・複雑・自社に合わない・使いこなせる気がしない」で断念、
  もしくは導入したが定着せず解約した経験がある
- ChatGPTは触ったことがあるが「業務システムをAIで作れる」とは思っていない

### 第2ターゲット: 営業部門の責任者・DX担当者
- 経営層から「AIで何かやれ」と言われているが、何から手を付けるべきか分からない
- 現場のツール不満（入力が面倒・欲しいレポートが出ない）を解決する武器が欲しい

### 第3ターゲット: 士業・コンサル・制作会社など「顧客に提案する側」
- 本ノウハウを自分の顧客への提供メニューに転用したい層（単価が高く決断が速い）

## 顧客の痛み（Before）

| 痛み | 現状の姿 |
|---|---|
| SaaSが合わない | 月額を払い続けても自社の営業フローに合わず、結局Excel併用 |
| 開発は高すぎる | 受託見積は300万円〜、仕様変更のたびに追加費用と数週間の待ち |
| AI活用が進まない | ChatGPTで文章は作れるが、業務の仕組みには落とせていない |
| 営業が属人化 | ヨミも次アクションも担当者の頭の中。会議は「確認」で終わる |
| 変化に追いつけない | 「作れる会社」と「借りるだけの会社」の差が開いていく焦り |

## 提供する変化（After）

**機能の説明ではなく「顧客の状態変化」で定義する。**

1. **作る側に回れる** — 外注も高額SaaSもなしに、自社専用の営業システムを
   自分の手（＝AIとの対話）で立ち上げ、翌日から改修できる状態になる
2. **要件を言語化できる** — 「何となく不便」を、AIに正しく伝わる要件・設計に
   翻訳するスキルが身につく（これはCRM以外の全業務に転用可能な一生モノ）
3. **営業が仕組みになる** — 完成するのはツールだけではない。週次レビュー・ヨミ管理・
   危険案件検知という「売上を作る営業の型」がシステムごと手に入る
4. **コストが桁で変わる** — 受託300万円・SaaS年50万円の世界から、
   月数千円のインフラ費＋自分の時間、の世界へ
5. **社内にAI開発の前例ができる** — CRMは第1弾。同じ進め方で経理・採用・
   マーケの業務OSを増やしていける「社内の勝ちパターン」を獲得する

## ベネフィットの一言化（エレベーターピッチ）

> 「プログラミング未経験の経営者が、AIとの対話だけで9日間で自社専用CRM/SFAを
> 本番稼働させた全記録と再現手順。買うのはツールではなく、
> **"自社の業務システムを自分で作り続けられる能力"** です。」

## 機能→ベネフィット変換表（LP・営業トークで使う）

| 商品に含まれるもの（Feature） | 顧客ベネフィット（Benefit） |
|---|---|
| 実プロジェクトの全開発記録（109コミット分の意思決定） | 何をどの順番で作ればいいか迷わない。失敗を先回りで回避できる |
| プロンプト・指示の実例集 | AIへの「正しい頼み方」を真似するだけで再現できる |
| 要件定義・設計書テンプレート | 自社の営業フローを書き込むだけでAIに渡せる仕様書が完成する |
| Supabase/RLS等の構成解説 | 「動くだけ」でなく、社員に使わせられるセキュリティ水準に届く |
| 週次レビュー・ヨミ管理の営業メソッド | システムと同時に営業マネジメントの型が導入できる |
| 無償アップデート（章・テンプレ追加） | 買った後も価値が増え続ける。陳腐化しない |

## 訴求しないこと（誠実さの線引き）

- 「誰でも1日でできる」とは言わない → 「経営者の本気の1〜2週間」と正直に言う
- 「エンジニア不要で何でも作れる」とは言わない → 適用範囲と限界（大規模・
  ミッションクリティカル領域は専門家併用）を明示する。この誠実さが10万円の信頼を作る
