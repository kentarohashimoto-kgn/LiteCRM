# 第6章 ツールを置き換えていった記録

> この章を読み終えると：CRM本体の周りにあるツール群（タスク管理・マインドマップ・
> 案件と原価の管理・営業分析）を自作側に寄せる判断基準と、置き換えの本当の効果が
> 「月額の削減」ではなく「データが1箇所にあること」だと分かります。

---

## 6-1. 実録：置き換えは「計画」ではなく「引力」で起きた

最初に正直に書くと、私は「ツールを何個置き換えるぞ」と計画したわけでは
ありません。CRMに営業データが集まり始めると、**周辺の仕事が勝手に
引き寄せられてくる**のです。

- 商談に次回アクションを書く → それはタスクでは？ → タスク管理が中に欲しくなる
- 案件に金額がある → 外注費を並べれば粗利が見える → 原価管理が中に欲しくなる
- 来週の商談が一覧できる → カレンダーと突き合わせたい → マインドマップで
  週の全体像を描きたくなる

置き換えの順番は、この「引力」の強い順でした。バラバラのツールにコピペで
橋を架けていた場所から順に、システムの中へ取り込んでいく。
だから置き換えるたびに、**転記という仕事が1つずつ消えていきました**。

## 6-2. 実録：タスク管理 ― 6日間でAsana級に育てた記録

タスク機能そのものは初日のMVPから入っていました（ただの一覧でした）。
それが7月中旬、6日間で市販ツール級に化けます。記録から抜粋します。

| 日付 | 追加したもの |
|---|---|
| 7/12 | ボードのグルーピング切替（進捗/優先度/ラベル）・セクションのドラッグ並び替え |
| 7/12 | 全画面共通の更新中オーバーレイ＋完了アニメーション（記録に「**Asana風**」とある） |
| 7/14 | 完了で完了列へ自動移動・列内ドラッグ・優先度既定順・カード色 |
| 7/15 | タスクに説明とURLリンク |
| 7/18 | **ガントチャート（タイムライン）・タスク依存関係・マイルストーン** |
| 7/18 | **サブタスク・繰り返しタスク** |
| 7/18 | **タスクコメント・@メンション** |

7/18(土)の3本は、F-201/202/203という要件書をまず書いてから実装しています
（第4章の作業指示書方式）。ガント・依存関係・サブタスク・メンションが揃った
時点で、社内のタスク管理をこちらに寄せました。

ここで気づいたことがあります。市販ツールの機能一覧は立派に見えますが、
**自社が本当に使う機能は2割**です。その2割を特定して作れば、6日で追いつける。
そして自作のタスクは**案件・商談と最初からつながっています**。
「この案件の提案後フォロータスク」が自動で生まれる（7/4のWO-02で実装）――
これは単体のタスク管理ツールには原理的にできないことです。

## 6-3. 実録:マインドマップ ― 「今週の頭の中」を自動で描く

7/25の記録で、マインドマップ機能を追加しています。ただの作図ツールでは
ありません。

> feat(mindmap): 日付下を4分類に整理し、**Googleカレンダー取り込み**を実装
> feat(mindmap): マップを本人限定にし、**CRMとカレンダーの予定を突合して統合**する
> fix(mindmap): 突合が社内定例を誤って商談と統合しないようにする

Googleカレンダーの予定と、CRM側の商談・案件・タスクを突き合わせ、
**今週・来週の全体像マップを自動生成**します。私はこれを週初に開いて、
準備が漏れている商談（予定はあるのに事前リサーチが書かれていない、等）を
見つけるのに使っています。3つ目の記録が示すとおり、社内定例まで商談扱いに
してしまう誤判定をその日のうちに直しました。自動化は一発では当たりません。
使いながら判定を教え込む前提で作るものです。

作図ツールとしてのマインドマップが欲しいなら市販品で十分です。
**データとつながったマインドマップ**が欲しかったから、作りました。
置き換え判断の分水嶺はいつもここです――「そのツール、うちのデータと
つながったら何ができる？」

## 6-4. 実録：案件・原価・稼働 ― 粗利がリアルタイムになった

案件管理と原価管理は、7月に一気に育てた領域です。

- 7/12：**稼働報告（週次実績記入→承認→原価管理連動）** を実装。
  同日、アクティブ人材台帳へ拡張し**41名分のデータを登録**
- 7/23〜24：原価管理にカレンダー表示・責任者列・
  **「見込み」タブ（継続/新規の受注見込みと人員手配）** を追加
- 7/24〜25：案件のフェーズ紐づけ・統合タイムライン化

流れとしては、外部パートナーの稼働時間が承認つきで集まり、案件の原価に
自動で載り、受注見込みと人員の手配状況が同じ画面に並ぶ、という形です。
それまで月末にスプレッドシートで締めていた「この案件、結局いくら残るのか」が、
**週次で、しかも承認済みの数字で**見えるようになりました。

これは会計ソフトの置き換えではありません（会計は会計ソフトの仕事です）。
置き換えたのは、会計ソフトに入る前の**「案件別の採算を組み立てるための
スプレッドシート作業」**です。置き換え対象を見極めるときは、この解像度で
考えてください。「ツールを置き換える」のではなく「作業を置き換える」のです。

## 6-5. 実録：営業分析 ― 置き換えの最終形は「つながった分析」

分析画面は初日から段階的に増え続けました。営業マン別・商品別・流入経路別
（初日）、トレンド分析（6/18）、施策ROI分析（6/26）、失注/成約分析（7/12）、
そして7/29〜30のSEO分析基盤で、ついに
**「検索キーワード→サイト訪問→問い合わせ→商談→受注金額」**が1本につながりました
（7/29の記録「WO-31 集客アトリビューション（着地ページ→問合せ→商談→受注金額）」）。

単体のBIツールやアクセス解析を契約しても、この1本線は引けません。
マーケのデータと営業のデータが**別のツールに住んでいる**からです。
置き換えの本当の効果はここに尽きます。月額の節約は嬉しいおまけで、
本体は**全部のデータが同じ場所にあるから、境界をまたぐ問いに答えられる**こと。
「7月の展示会、受注ベースで元が取れたのか？」に、画面1つで答えられます。

## 6-6. 実録：寄せなかったもの

全部を自作に寄せたわけではありません。判断の記録として残します。

- **会計・給与** ― 法令対応が本体の領域。作らない（会計ソフトと併用）
- **メールそのもの** ― Gmailを置き換えるのではなく**つなぐ**（第4章）。
  受信箱は今もGmailです
- **チャット** ― 同じく置き換えず、通知を流す先として連携（Google Chat）
- **カレンダー** ― Googleカレンダーが主。CRM側は取り込んで突合する側

法則：**世の中標準のコミュニケーション基盤と法令領域は置き換えない。
自社の業務ロジックが乗るものだけ寄せる。**

## 6-7. 標準：置き換え判断の手順

1. **ツール棚卸し** ― 契約中のツールと月額、それぞれで「やっている作業」を列挙
2. **転記マップ** ― ツール間でコピペ・二重入力している線を洗い出す。
   線が太い順が置き換え優先順
3. **2割機能の特定** ― そのツールで実際に使っている機能だけ書き出す
   （全機能の再現を目指さない）
4. **つながり価値の確認** ― CRMのデータとつながると何が新しくできるか、を
   1行で書けるものだけ作る
5. **置き換えない判定** ― 法令領域・世間標準のコミュニケーション基盤は連携に留める
6. **並行期間は2週間まで** ― 旧ツールと並走させ、締め日を決めて片方を止める
   （並走が長引くと二重入力が定着し、どちらも死にます。うちはNotionのヨミ表を
   移行当日に止めました）

## 章末付録①：この章のプロンプト実例

**（1）2割機能の置き換え設計**

```text
現在タスク管理に市販ツールを使っていますが、このCRMに統合したいです。
まず、私たちが実際に使っている機能だけを対象にします：
- ボード表示（進捗列ごと）、担当者、期限、優先度、コメント
- 使っていない機能（ガント、時間計測、自動化ルール）は作らない
条件：
- タスクは案件・商談に紐づけられること（ここが市販ツールとの差別化点）
- 案件で「提案済み」にしたら7日後フォロータスクが自動生成されること
まず画面案と、市販ツールからのデータ移行方法を提示してください。
```

**（2）つながった分析を作る**

```text
別々に見ているデータを1本につないだ分析画面を作ってください。
つなぎたい線：展示会（施策）→ 獲得リード → 案件化 → 受注金額 → 施策の費用対効果
- 施策ごとに「費用・リード数・案件化数・受注額・ROI」を1行で
- 期間で絞り込めること
- 元データはすべて既存テーブルにあります。新しい入力項目は増やさないでください
```
