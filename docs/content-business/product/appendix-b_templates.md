# 付録B 書き込み式テンプレート集

そのまま複製して書き込む様式集です。すべて本文の実録から抽出した形式で、
空欄を埋めれば「AIに渡せる状態」になるよう設計しています。

## B-2 ガードレール雛形（第8章）

```markdown
# ガードレール（この文書に反する変更はしない。迷ったら私に確認する）

## 環境（自分の環境名で埋める）
- リポジトリ：　　／作業ブランチ：　　（他ブランチへの書き込み禁止）
- データベース：　　／ホスティング：

## 鉄則
1. 秘密情報（キー・パスワード・接続文字列）をコードに書かない。環境変数のみ。
2. 新しいテーブルには、作成と同時にテナント札・RLSポリシー・更新日時を付ける。
3. 新しい機能・APIは既定で閉じる。明示的に許可した相手だけ実行できる。
4. 迷ったら加算的・非破壊・既存パターン踏襲。破壊的変更は事前に確認。
5. DB変更のたびにセキュリティ警告チェックを実行し、エラー0を確認する。
6. 小さくコミットする。大工事の前に静止点を作る。
7. 完了報告には、別ロールで実測検証できる手順を必ず添える。

## 失敗から足したルール（事故のたびに1行追加していく）
8.（日付：出来事→禁止事項）
```

## B-3 作業指示書（WO）雛形（第4章）

```markdown
## WO-（番号）：（件名）
- 目的：（1行。なぜやるか）
- 変更範囲：（触ってよい画面・データ・ファイル）
- やってはいけないこと：（既存仕様の変更禁止箇所・触ってはいけない場所）
- 完了条件：（測定可能に。「◯◯が◯秒で表示される」「◯件で検証済み」）
- 検証方法：（誰が・どのアカウントで・何を確認するか）
```

## B-5 ツール棚卸しシート（第6章）

| 契約中ツール | 月額 | 実際にやっている作業 | 使っている機能（2割） | 他ツールへの転記 | 判定 |
|---|---|---|---|---|---|
|  |  |  |  | あり/なし | 置換/連携/維持 |

判定基準：
- **置換**＝自社の業務ロジックが乗る＋CRMのデータとつながると新しい価値が1行で言える
- **連携**＝世間標準のコミュニケーション基盤（メール・チャット・カレンダー）
- **維持**＝法令領域（会計・給与）
