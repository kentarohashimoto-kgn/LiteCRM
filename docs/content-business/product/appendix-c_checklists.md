# 付録C セキュリティ&本番化チェックリスト（合本・印刷用）

本文各章のチェックリストを、時系列で1冊にまとめた実行用の合本です。
上から順に使えば、Day 0から運用まで「確認漏れで事故る」経路を塞げます。
各項目の背景は（　）内の章を参照。

---

## C-1 Day 0：作る前（第1章）

- [ ] 対象業務は「自社の型が強い社内業務」である（決済・医療・不特定多数公開ではない）
- [ ] 利用者ロールと「見えてよい範囲」を要件定義書に書いた（安全は要件から始まる）
- [ ] 自社固有情報はコードに直書きせず設定データにする方針を明記した
- [ ] 「今回作らないことリスト」がある

## C-2 初日：最初の構築（第2章・第13章）

- [ ] デモモード（サンプルデータ）で全画面を確認した
- [ ] 実認証・永続保存・RLS（データベース側の権限制御）が入った
- [ ] **別ロールのアカウントで実測**し、見える件数を数えて記録した
- [ ] 公開手順書をAIに書かせて保存した
- [ ] 機械監査（セキュリティAdvisor）を実行し**エラー0**を確認した
- [ ] 実データの一括投入・社員展開は**まだ**していない

## C-3 毎回の作業（第8章の7原則を日次に落としたもの)

- [ ] 指示に「変更範囲」と「やってはいけないこと」を書いた
- [ ] 秘密情報をチャット・コードに貼っていない（環境変数のみ）
- [ ] DB変更をしたら機械監査を回した（エラー0・警告を増やさない）
- [ ] 小さくコミットした（大工事の前は静止点）
- [ ] 完了報告に実測可能な検証手順を出させた

## C-4 実データを入れる前（第3章・第15章）

- [ ] 書式ゆれ分析→移行ルール確定→リハーサルの順でやった
- [ ] 移行は全置換でやり直せる方式になっている
- [ ] 実データ規模テスト（想定最大件数）で欠落と速度を確認した
- [ ] 件数・金額の突合せが元データと一致した
- [ ] 移行完了直後の静止点を作った

## C-5 本番化ゲート：社員に配る前（第9章の7区画・要約版）

**認証**
- [ ] 未ログインで業務URLに入れない（シークレットモードで実測）
- [ ] 初期パスワードの初回変更を案内する／機械攻撃対策（CAPTCHA等）がある

**権限**
- [ ] 権限がRLS（DB側）で強制されている。画面の出し分け頼みではない
- [ ] 別ロール実測が設計表と一致（件数記録あり）
- [ ] 脇道（検索・集計・CSV出力・通知本文）の点検を実施した

**データ保全**
- [ ] 自動バックアップが有効
- [ ] **復元の練習を1回やった**（最重要。「取れているはず」は存在しない）
- [ ] 削除はゴミ箱方式。自動処理・削除の入り口は合言葉未設定なら全拒否（fail-closed）

**秘密情報**
- [ ] コード・文書内の秘密情報0件（機械スキャン済み）
- [ ] 環境変数台帳がある。過去に漏れたキーは再発行済み

**監視と記録**
- [ ] エラー監視が入っている／操作の監査ログがある
- [ ] 機械監査エラー0

**運用準備**
- [ ] 社員向け1枚マニュアル／メンバー発行・停止手順／困ったときの窓口／変更告知の方法

**個人情報・法令**
- [ ] 保存する個人情報の一覧を書き出した（名刺・録音は特に）
- [ ] 一斉メールは特定電子メール法対応（同意・送信者表示・配信停止）
- [ ] 退職者アカウントの停止手順がある

## C-6 専門家との線引き（第9章）

- [ ] 🔴に該当しない：決済処理／法令上の機微情報／不特定多数への公開
  （該当するなら、その領域は専門家なしで進めない）
- [ ] 🟡に該当するか自覚している：社外パートナーのログイン／基幹業務の完全依存
  （該当したら：権限実測の徹底＋年1回の外部監査を予算化）

## C-7 定期便（第16章）

- [ ] 週次：週末バッチの最後に機械監査エラー0を確認してから閉じる
- [ ] 月次：重要数字の突合せ（別ルートの集計と照合）／現状仕様書の更新
- [ ] 機能10個ごと：全体監査（機械監査全件精査＋別会話のAI攻撃者レビュー＋実測検証）
- [ ] 監査報告書を日付つきで保存した

## C-8 事故が起きたら（初動の順序）

1. **止血**：該当機能を止める（画面から外す／入り口を閉じる）。原因究明より先
2. **記録**：何が・いつから・誰に影響したかをメモ（監査ログが効く場面）
3. **巻き戻し判断**：静止点・バックアップに戻すか、前進修正か。迷ったら戻す
4. **修正と実測検証**：直したら別ロール・実データで確認
5. **再発防止**：ガードレールに1行追加。初期設定で防げるなら設定を変える
6. **報告**：影響を受けた人に正直に。隠すと信頼のほうが消えます
