# 第11章 準備：環境構築とAIツールの契約

> この章を読み終えると：開発を始めるのに必要な4つのサービスの契約と初期設定が
> 完了し、費用の全体像（無料でどこまでいけるか・いつ課金するか）が分かります。
> 所要時間の目安は1〜2時間。ここは「作業」の章です。淡々といきましょう。

---

## 11-1. 全体像 ― 必要なのは4つだけ

私が8週間使った構成は、次の4つです。それぞれの役割を先に掴んでください。

| サービス | 役割 | 例えるなら | 費用 |
|---|---|---|---|
| **Claude Code**（AIコーディングツール） | あなたの指示でコードを書く | 開発者そのもの | 有料（下記） |
| **GitHub** | すべての変更を記録・保管する | 工事の全記録簿 | 無料 |
| **Supabase** | データベース・ログイン認証・権限制御 | データの金庫と受付 | 無料枠から |
| **Vercel** | システムをインターネットに公開する | 店舗の土地と建物 | 無料枠から |

この組み合わせを選んだ理由は3つあります。
（1）どれも無料枠で本格的に始められる、（2）AIがこの組み合わせに慣れて
おり指示が通りやすい、（3）認証・権限（RLS）・自動バックアップという
安全装置がSupabaseに標準で付いている――第2部で見たとおり、
安全装置は後付けが一番高くつくので、最初から持っているものを選びます。

なお、ツールは日々進化しています。ここに挙げた各サービスの画面や
プラン内容は変わり得ますが、**「AI・記録・データ・公開」の4役割**という
構造は変わりません。画面が本書と違ったら、役割で読み替えてください。
（大きな変化があれば、本教材のアップデートで追随します）

## 11-2. 費用の実額 ― 8週間でいくらかかったか

私の実績です。誇張なしの生の数字を出します。

| 項目 | 金額 | 備考 |
|---|---|---|
| Claude Code | 【橋本追記11-1：契約プランと月額】 | 開発の主役。ここが最大の投資 |
| GitHub | ¥0 | 無料プランで完結 |
| Supabase | ¥0（8週間無料プランのまま） | 東京リージョン・無料枠で社員利用まで到達 |
| Vercel | 最初の6週間¥0 → 7週目からPro（月20ドル） | 課金理由は後述 |
| エラー監視（Sentry） | ¥0 | 無料枠で十分 |

**要点：インフラ費は月数千円規模。最大の費用はAIツールと、あなたの時間です。**

Vercelを有料化した判断（7/18）は第4章に書いたとおりです。メール連携と
夜間の自動処理を本格稼働させる段階で、無料プランの「定時実行は1日1回まで」
制限が本筋の障害になった。**制限を回避する工夫に時間を使い始めたら、
課金のサイン**――これがこの教材の課金基準です。逆に、その段階までは
無料で粘って構いません。私は6週間無料で走りました。

## 11-3. 手順1：GitHubのアカウントとリポジトリ

最初に「記録簿」を作ります。すべての作業はここに記録され、
いつでも巻き戻せるようになります（第8章・原則6の土台）。

1. github.com でアカウント作成（会社のメールアドレスで）
2. 新しいリポジトリを作成。名前は自由（例：`our-crm`）。**Private（非公開）を選ぶ**
3. 完了条件：空のリポジトリのページが表示されている

## 11-4. 手順2：Claude Codeの契約と接続

1. claude.com でアカウントを作成し、有料プランを契約
   （プラン選びの考え方：まず標準的なプランで始めて、使用量の上限に
   当たる週が続いたら上げる。最初から最上位にする必要はありません）
2. Claude Codeを開き、手順1のGitHubリポジトリに接続する
   （画面の案内に従ってGitHub連携を承認）
3. 完了条件：Claude Codeの画面で、あなたのリポジトリを開いた状態で
   AIに話しかけられる

ここで最初のひと言を打ってみてください。

```text
このリポジトリで、自社用のCRM/SFAを作っていきます。
まだ何も作らないでください。まず、あなたが私に確認したいことを5つ挙げてください。
```

AIが質問してきたら、接続は成功です。（作るのは第13章から。今日は環境だけ）

## 11-5. 手順3：Supabaseのプロジェクト作成

データの金庫を作ります。

1. supabase.com でアカウント作成（GitHubアカウントでログインできます）
2. New Project → プロジェクト名（例：`our-crm`）→ リージョンは **Tokyo**
   （日本で使うなら必ず東京を。海外リージョンだと全操作がワンテンポ遅れます。
   私も東京で運用しています）
3. データベースのパスワードが発行される → **パスワード管理ツールに保存**
   （このパスワードはコードに書きません。第8章・原則1）
4. Project Settings → API から、URLと公開キー（anon key）の場所を確認しておく
5. 完了条件：プロジェクトのダッシュボードが開き、URLとキーの場所が分かる

## 11-6. 手順4：Vercelのアカウント

公開の土地を押さえます。

1. vercel.com でアカウント作成（これもGitHubログインが楽です）
2. まだ何もデプロイしません。アカウントだけ。実際の公開は第13章で
   AIに手順書を書かせてから行います（初日の私がそうしたように・第2章）
3. 完了条件：Vercelのダッシュボードにログインできる

## 11-7. 手順5：環境変数の台帳を作る

4つのサービスの契約情報・キーの一覧表を、**パスワード管理ツールの中に**
作ってください（Excelやメモアプリに生のキーを貼らない）。

| 名前 | どこで発行 | 何に使う | 保存場所 |
|---|---|---|---|
| SUPABASE_URL | Supabase設定画面 | アプリがDBを見つける住所 | Vercel環境変数 |
| SUPABASE_ANON_KEY | 同上 | 公開してよい方のキー | 同上 |
| SUPABASE_SERVICE_ROLE_KEY | 同上 | **絶対非公開**の管理者キー | 同上（サーバー専用） |
| DBパスワード | プロジェクト作成時 | 直接DBを触るとき | パスワード管理ツールのみ |

「どのキーがどこにあるか」を最初に台帳化しておくと、第8章の総点検も
第9章のゲートも一瞬で終わります。散らかってから作ると3倍かかります。

## 11-8. 無料枠の「ここまでは大丈夫」ライン

私の実測ベースの目安です（プラン内容は変わり得るので、契約時に最新を確認）。

- **Supabase無料枠**：社内数十人・数万レコード規模のCRMなら十分動きます。
  うちは案件681件・リード1万件超・社員利用でも無料枠のままでした。
  注意点は「1週間使わないと一時停止する」仕様（毎日使う業務システムなら実質無関係)
- **Vercel無料枠**：画面の公開だけなら余裕。引っかかるのは
  **定時実行(cron)の回数制限**（私が踏んだ罠・第3章）と商用利用の規約。
  社員が業務で使う段階になったらProへ（月20ドル）
- **Sentry無料枠**：エラー監視は無料枠で十分
- 傾向として無料枠の壁は「容量」より先に**「自動処理・頻度・商用条件」**に来ます

| # | やること | 完了条件 |

| 2 | Claude Code契約＋リポジトリ接続 | AIが質問に答える |
| 3 | Supabaseプロジェクト（東京） | URL・キーの場所が分かる |
| 4 | Vercelアカウント | ダッシュボードに入れる |

## 章末付録：つまずき先回り表

| 症状 | 原因の見当 | 対処 |
|---|---|---|
| GitHub連携の承認画面が出ない | ブラウザのポップアップブロック | 別ブラウザ/シークレットで再試行 |

| どのプランにすべきか迷って止まる | ― | 全部無料/標準で開始。課金判断は「制限回避の工夫を始めたとき」 |
