# 購入者への納品導線 設計書

購入から閲覧・アップデート受領までの流れと、購入者専用ページ・PDFの体裁設計。
方針：**すべて自前（バイブコーディングで構築）**。それ自体が商品の実演になる。

---

## 1. 購入フロー全体図

```
[LP] ─ クレカ ─→ [Stripe Payment Link] ─→ 決済完了
  │                                         │
  │                                         ▼
  │                              [自動メール] 専用ページの招待
  │                                         │
  └─ 法人・請求書払い ─→ [問い合わせフォーム] ─→ 見積書・請求書
                              │                     │
                              └──── 入金確認 ────────┘
                                                    ▼
                                    [購入者専用ページ]（要ログイン）
                                      閲覧・PDF DL・更新通知
```

- クレカ経路は完全自動（深夜の購入でも24時間以内どころか即時に案内が届く）
- 法人経路は手動1往復（freeeで請求書発行→入金確認→招待メール）
- どちらも最終的な納品物は同じ「購入者専用ページ」

## 2. 購入者専用ページの構成

実装はこのCRMと同じ構成（Next.js + Supabase Auth）を最小化した別プロジェクト。
教材第2章の「デモモード→本番化」の手順そのままで作れる規模。

| ページ | 内容 |
|---|---|
| ログイン | メール＋パスワード（購入時に発行、初回変更を案内） |
| ホーム | 更新履歴（新着を最上部）／読み進めチェック（章ごとの既読管理） |
| 本文 | 第0〜16章＋付録A〜D。1章1ページ。章末に「次の章へ」導線 |
| テンプレート | 付録Bの各様式をコピペ可能なテキスト＋Markdownダウンロード |
| プロンプト集 | 付録Aをワンクリックコピー可能なUI（実用性が跳ねる） |
| お知らせ | アップデート告知・価格改定の予告 |

設計上の要点：

- **転売対策は「利便性」でやる** ― DRMで縛るより、専用ページが便利
  （更新が届く・コピペできる・既読管理）であるほどPDFの横流しは魅力を失う。
  PDFには購入者メールの透かしを入れる程度に留める
- **更新通知はメール＋ページ内の両方** ― 「買った後も増える」体験が
  この商品の保証そのものなので、更新のたびに必ず知らせる
- 権限は購入者ロールのみの単純構成だが、**RLS必須・Advisorエラー0**は
  教材と同じ基準を守る（教材の販売ページが教材の基準を破っていたら台無し）

## 3. PDF版の体裁設計

- 構成：表紙／はじめに（第0章）／目次／本文16章／付録4点／更新履歴／奥付
- 版面：A4縦・1段組み・本文横書き。余白広め（画面読み層と紙読み層の両対応）
- 表紙：LPと同じダーク基調＋ヒートマップのグラフィック（ブランド連続性）
- 各章扉：章番号・タイトル・「この章を読み終えるとできること」（既存の冒頭文を流用）
- プロンプト部分は等幅・グレー背景ボックスで視認性を確保
- 透かし：フッターに購入者メールアドレスを小さく差し込み（購入処理時に自動生成）
- 生成方法：Markdown原稿→HTML→PDF の自動変換をスクリプト化し、
  改訂のたびに再生成できるようにする（手作業の組版はしない）

## 4. アップデート運用（納品後の約束の実行）

1. 教材リポジトリ（docs/content-business/product/）を正とし、
   改訂は通常のコミットで管理
2. 章追加・改訂をリリースする際：専用ページ反映→PDF再生成→
   更新履歴に追記→購入者へメール告知（変更点3行サマリ付き）
3. 価格改定は「次回追加の予告」とセットでLP・お知らせに掲載
   （早期購入インセンティブの実行）

## 5. 構築の段取り（実働見積り）

| # | 作業 | 規模 |
|---|---|---|
| 1 | Stripe Payment Link発行＋テスト決済 | 1時間 |
| 2 | 専用ページの最小版（ログイン＋本文閲覧＋更新履歴） | 週末1日（教材第13章の手順そのまま） |
| 3 | 決済完了→アカウント自動発行の接続 | 半日 |
| 4 | PDF自動生成スクリプト | 半日 |
| 5 | テンプレDL・プロンプトコピーUI | 後追いでよい（v1.1） |

※2〜4はこのリポジトリと同じ構成のため、私（AI）に指示すればそのまま構築可能。
着手指示があれば、専用ページのリポジトリ設計から始められる。

## 6. 決めること

- [ ] 専用ページのドメイン（LPと同一ドメイン配下を推奨：/members 等）
- [ ] 透かし入りPDFの要否（推奨：入れる。ただし本文の読みやすさ優先で控えめに）
- [ ] 請求書払いの入金確認フロー（誰が・どの頻度で確認するか）
