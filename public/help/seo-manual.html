1. 何のためにやるのか（ゴール）

このシステムの目的はひとつ。「検索で見つけてもらい、問い合わせをもらい、月300万円の売上をつくる」ことです。すべての画面・すべての作業はこの逆算に紐づいています。

売上目標月300万
←
受注1.7件成約率48.5%
←
問い合わせ20件CVR 2%
←
セッション1,000CTR 3.8%
←
検索表示26,300/月
図1｜逆算ファネル：売上から逆算すると「月26,300回、検索結果に表示される」が必要になる。数字は自社CRM実績から算出
なぜ逆算か: 「アクセスを増やそう」では何をどれだけやればいいか分からない。売上から逆算すれば「今週は表示回数をあと◯◯増やす記事を書く」と作業が数字で決まる。現在地とのギャップは戦略ボードでいつでも見られる。

2. 全体像 — 7画面のつながり

7つの画面は「作戦を立てる → 記事を作る → 順位を測る → 直す → 売上で確かめる」の一本道でつながっています。紫の画面は毎朝4時に自動で動くので、人がやるのは緑の画面だけです。

③ 記事を書く・直す記事ネタ・ブログ／HP担当
↓ 公開・リライトの結果をGoogleが評価（2〜4週）
⚙ 自動取込（毎朝4時）Search Console / GA4 → CRM
→
④ KW順位表狙った語が何位か・週次で確認
→
⑤ 改善提案直す価値の高い順に提案

⑥ 施策実行指示書を別AIで実施→公開URLを貼って反映記録

⑦ 集客サマリー問い合わせ・売上で効果を確かめる

図2｜画面のつながり：①→⑦がひと回りのループ。④以降は自動取込データが燃料になる
なぜ複数画面に分かれているか: 「作戦」「設計」「計測」「実行」「検証」は判断の種類が違うため。1画面に全部入れると、毎週やること（④⑤）と月1でやること（①）が混ざって迷子になる。迷ったら図2の左上（①戦略ボード）から右下へ順にたどれば現在地が分かる。

3. 運用リズム — いつ・何を・どれだけ

毎日やることはありません（取込は自動）。人の作業は週1回のチェックと、記事の執筆・リライトだけです。

頻度使う画面やること目安時間
毎朝4時（自動）Search Console / GA4からデータ取込 → 問題検知 → 提案作成。人の作業なし—
週1回
（月曜推奨）		④ KW順位表前週比で順位の動きを確認。「対策ページと不一致」バッジ（カニバリ兆候）と「拾い物」をチェック10分
〃⑤ 改善提案 → ⑥ 施策実行提案を期待値の大きい順に承認/却下。承認済み施策の進み具合を確認、公開・修正が済んだものはURLを貼って反映を記録10分
随時② 記事プラン → 記事ネタ難易度の低いプランから順に起票→執筆。公開したら対策URLを登録記事による

4. 週次PDCAの回し方

週1回・15分のチェックをPDCAに当てはめると、使う画面がそのまま決まります。

P狙いを決める

  • 戦略ボード：注力クラスタ・フェーズ
  • 記事プラン：次に書く記事（難易度低い順）
→

D作る・直す

  • 記事ネタで執筆 → 公開 → 対策URL登録
  • 施策実行：指示書（プロンプト）を別AIやHP担当に渡して作成・修正 → 公開したページのURLを貼って反映を記録
↑
↓

A次の一手を選ぶ

  • 改善提案：期待値の大きい順に承認
  • 効かなかった施策は別の打ち手へ
←

C測る

  • KW順位表：前週比・ギャップの変化
  • 集客サマリー：問い合わせ・売上への波及
図3｜週次PDCA：C（測る）とA（選ぶ）は毎週15分。P・Dは記事執筆のペースに合わせて
なぜ「提案の承認」がA（改善）なのか: 何を直すべきかはシステムが毎朝データから検知して期待値順に並べてくれる。人の役割は「やる/やらないの判断」に絞る設計。全部自分で分析する必要はない。

5. ケース別フロー（4シナリオ）

ケースA｜新しい記事を書いて上位を取る

  1. 記事プランで難易度の低い未着手プランを選ぶ自分 — 検索数の大きい語からではなく勝てる語から
  2. 「記事ネタに起票」→ 記事ネタ・ブログで執筆自分 — メインKW1語＋サブKW数語を1記事で狙う
  3. HPに公開HP担当 → 記事プランに対策URLを登録自分
  4. 2〜4週待つ（Googleの評価には時間がかかる）自動
  5. KW順位表で順位が付いたか確認自分 — 「未対応」→「21位以下」に変われば第一関門クリア

ケースB｜改善提案が来た（毎週の定常運用）

  1. 改善提案を開き、期待値の大きい順に内容を読む自分
  2. 納得できるものを「承認」→ 施策カードが自動作成自分 — 迷う/情報不足なら「様子見」（7日後に再判断）
  3. 施策実行の指示書（プロンプト）をコピーして別AIやHP担当に渡すHP担当
  4. 公開・修正が完了したらそのページのURLを貼って「反映を記録」を押す自分 — ここから効果検証が始まる
  5. 検証予定日以降、順位・クリックの変化で当たり外れを確認自動

ケースC｜順位が落ちた・カニバリを見つけた

  1. KW順位表の前週比▼や「対策ページと不一致」バッジに気づく自分
  2. 対策ページと「実際に表示されているページ」を両方クリックで開いて見比べる自分
  3. 翌朝の自動検知で改善提案が出るのを待つ／急ぐ場合はSEO設定の「今すぐ取込」自動
  4. 提案を承認してケースBの流れへ自分

ケースD｜問い合わせが入った（成果の確認）

  1. HPフォームからの問い合わせがリードに自動登録（着地ページ・検索流入元つき）自動
  2. 集客サマリーの「ページ別売上貢献」で、どの記事が問い合わせ・売上を生んだかを確認自分
  3. 売上を生んだ記事のパターン（テーマ・型）を記事プランの次の執筆に反映自分

6. 各画面の目的 早見表

画面ひとことで言うと開くタイミングここから次に行く画面
① 戦略ボード売上からの逆算と作戦。「なぜやるか」の原点月1記事プラン
② 記事プランどのページでどの語を取るかの設計図（1検索意図=1ページ）執筆のたび記事ネタ・ブログ（起票）
④ KW順位表狙った語が何位か。SEOの成績表週1改善提案／実ページ（リンク）
⑤ 改善提案直す価値の高い順の提案。承認/却下だけすればいい週1施策実行（承認で自動作成）
⑥ 施策実行承認済み施策のかんばん。公開URLを貼って反映記録週1集客サマリー（効果確認）
⑦ 集客サマリー表示→問い合わせ→売上のファネル。成果はここで見る月1〜週1戦略ボード（作戦見直し）

7. 落とし穴 5つ

①公開URLの貼り忘れ。記録しないと効果検証が始まらず、施策が効いたか永久に分からない。公開・修正が済んだら必ずその日にURLを貼って「反映を記録」を押す。
② 1語1記事にしてしまう。似た語ごとに記事を量産するとカニバリ（共食い）が起きてサイト全体が沈む。必ず記事プランの設計（1検索意図=1ページ）に従う。
③ 検索数の大きい語から書く。「生成AI研修」のような大物は大手が占有していて、今のドメイン力では届かない。難易度の低い語で実績を積んでから挑む。
④ 日々の順位変動に反応する。データは2〜3日遅れ・順位は日々揺れる。判断は週次の前週比で。毎日見ても得るものは少ない。
⑤ 記事を公開したのに対策URLを入れない。URL未登録だと順位計測とカニバリ検出が働かず、書きっぱなしになる。公開とURL登録はセット。
